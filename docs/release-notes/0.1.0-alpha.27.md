# devcontour-harness 0.1.0-alpha.27

Хранилище зависимостей pnpm, объявляемое в политике, команда уборки рабочих
деревьев завершённых попыток, более дешёвый поиск оставшихся процессов и
отказ до заведомо безуспешного вызова ревьюера. Обязательные gates, fencing и
привязка доказательств к SHA не меняются.

## Изменения

- **Хранилище зависимостей.** Необязательное поле
  `repositories[].dependencyStore` (`manager: 'pnpm'`, `lockfile`, `maxBytes`,
  `timeoutMs`). Seed собирается только из lockfile целевого ref и копируется
  в `<checkout>/.pnpm-store`. Исход пишется в `dependency-store.json`: `hit`,
  `partial` или `miss`. Отказ хранилища не стоит попытки: установка идёт
  обычным путём. Поддержан pnpm `>=9.15.0 <10.27.0`; границы описаны в
  `docs/compatibility.md`. Linux не проверялся.
- **`harness worktree-cleanup --state S [--dry-run]`.** Удаляет
  зарегистрированные деревья завершённых попыток; ветки, объекты и артефакты
  остаются. Незакоммиченные правки сначала сохраняются в patch. Дерево, которое
  нельзя доказуемо восстановить, не удаляется, а отказ назван. Деревья с Git
  LFS отказываются намеренно.
- **Поиск потомков.** Проверяются только процессы моложе команды: около 26 мс
  вместо 341 мс на команду.
- **Ревью.** Проверка плана и договора останавливается до вызова, который не
  может завершиться успешно. Открытые находки считаются по ID перед пределом
  раунда.
- **Коннектор.** Понятный отказ, если конфигурация с baseline исчезла после
  загрузки; `source-snapshot` снова закрепляет более раннюю ревизию.
- **Тесты.** У каждого прогона свой временный каталог, который удаляется в
  конце; чувствительные к нагрузке тесты ждут событий, а не таймеров.

## Обновление

Пакет alpha.26 остаётся неизменным. Перед обновлением остановите writers и
сохраните копию состояния. Преобразование состояния не требуется. Без поля
`dependencyStore` поведение установки не меняется.
