# devcontour-harness 0.1.0-alpha.76

`stateVersion`, `policyVersion`, `handoffVersion`, `reportVersion`,
`viewVersion` и `viewRevision` (`11`) прежние. Порядок обновления и отката —
`docs/upgrade.md`, раздел alpha.76.

Выпуск ускоряет сдачу тонкого режима: исполнитель гоняет только проверки
своей работы, тяжёлые сценарии других работ harness исполняет один раз —
после одобренного ревью.

## Поручение

- **`regressionGates`** — новое необязательное поле поручения
  (`WorkOrder`) и задачи draft самостоятельного плана: проверки цели,
  которые работа не меняет (сценарии других работ, которые она не должна
  сломать). `gates` — свои проверки работы; без `gates` своя область — все
  gates репозитория, кроме регрессионных. Нет поля — прежняя область одной
  фазой: старые планы, облегчённый и строгий режимы не меняются.
- Попытка закрепляет обе части в `requiredGates` (приёмка, результат и отчёт
  требуют PASS и регрессионных gates), регрессионную — в
  `attempts[].regressionGates`. Облегчённый и строгий режимы исполняют
  `gates` и `regressionGates` вместе, как одну область.
- `validate` и `plan-check` отклоняют неизвестную ссылку, gate в обоих
  полях, регрессионный gate, чья предпосылка (`dependsOn`) не входит ни в
  одну из областей, свой gate (без поля `gates`), требующий регрессионный,
  свою область без test gate и требование, привязанное к регрессионному
  gate. Digest области поручения (`approvedScope`) включает поле, только
  когда оно есть: digest прежних работ тот же.

## Тонкий режим

- **Порядок сдачи**: слияние с целью на чистом checkout → свои gates,
  проверки потребителей, требования → одно ревью → регрессионные gates в том
  же дереве и окружении → CAS. Отказ ревью возвращает сдачу исполнителю без
  регрессионных gates. Их провал после одобренного ревью — обычный провал
  gate: продолжение сессии получает хвост и строку о том, что ревью
  одобрило, а сломан сценарий другой работы; следующая сдача — снова свои
  gates и новое ревью (прежнее одобрение не переиспользуется).
- **Исполнитель** видит и гоняет только свои gates; регрессионные названы
  ему проверками harness, которые он не запускает. Раньше исполнитель
  гонял все gates поручения, в том числе многоминутные наборы других работ.
- **Планирование**: запрос плана просит в `gates` только свои проверки (по
  gate на каждый свой набор тестов, без glob или группы, которые захватывают
  тесты другой работы), а тяжёлые наборы других работ — в
  `regressionGates`.
- **Выпуск** не меняется: `review-release` гоняет полный набор gates на
  голове цели.
