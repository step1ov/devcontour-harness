# devcontour-harness 0.1.0-alpha.17

Меньше слепых повторов и ручных сбросов. Включает всё из
[0.1.0-alpha.16](0.1.0-alpha.16.md). Gates, правила находок, изоляция,
принятие target ref и `maxAttempts` не менялись; формат состояния получил
необязательные поля (ниже, «Совместимость»).

## Что нового

- **Класс входов в находке ревью.** Блокирующая находка со входом называет
  нарушенное свойство или критерий (`reproduction.property`) и класс входов
  (`reproduction.inputClass`) — генератор или семейство, а не экземпляр. Поле
  обязательно в схеме ответа runtime; ответ прежней формы без него
  разбирается. Класс пишется в реестр воспроизведений и на отклонённую
  попытку (`inputClasses`, пары `classified`); следующий writer получает
  задачу чинить класс.
- **Пробел приёмки.** `repairDecision` останавливает поручение с полем `gap`
  и причиной для ведущего, когда два отказа ревью подряд называют одно и то
  же необъявленное свойство с тем же классом входов (класс без регистра и
  лишних пробелов). Совпадение только свойства или только класса требует
  трёх отказов подряд: общий класс бывает у разных дефектов. Отказ
  окружения серию не меняет; отказ gate, другое название и новое основание
  поручения её обрывают. `explain` показывает то же. Объявленные свойства
  по-прежнему ведёт эпизод разбора.
- **Отказы окружения не тратят попытки.** Отказ окружения или провайдера и
  истёкшее владение не засчитываются в `maxAttempts`, и после кандидата.
  Предел у них свой: `MAX_NEUTRAL_FAILURES` = 3 на поручение (счётчик
  `neutralFailures`); на нём `retry` без сброса, выдача и восстановление
  отказывают, сброс человека обнуляет счётчик.
- **Штатная остановка не роняет работу.** `Runner.stop` помечает свои
  попытки: прерванная сохраняет черновик, получает `interrupted: shutdown`,
  а поручение возвращается в очередь (`ready`) без траты попытки и без паузы
  по классу отказа; после снятия паузы остановки следующая попытка
  продолжает с кандидата или черновика. Интегрированная попытка так не
  возвращается: это обычный отказ, хост получает `hooks.failed`.
- **Класс отказа `unfinished`.** `completed: false` исполнителя был
  `unknown` и останавливал работу без повтора, с сохранённым черновиком.
  Теперь это `unfinished`: повтор (предел одинаковых — 2) продолжает с
  черновика (`continuedFrom.kind: unfinished`) в пределах `maxAttempts` и
  `repairBudget`; для эпизода свойства отказ нейтрален.
- **Пустой результат только с механическим основанием.** Пустая реализация
  больше не отклоняется сразу: кандидат — сама база, gates задачи идут на
  ней, оба ревью отвечают схемой с обязательным `alreadySatisfied` (gates
  области задачи — хотя бы один test gate и все gates договоров проверки
  поручения — и основание). Принятие требует ещё механического основания,
  которое находит controller: договор проверки поручения со всеми gates в
  области задачи, или зависимость, чей принятый результат входит в
  проверяемый SHA и чей кандидат менял файлы области записи поручения.
  Основание пишется в evidence ревью (`alreadySatisfied.basis`). Без него —
  новый класс отказа `needs-lead`: остановка без повтора, решение ведущего.
  `engine.finish` повторяет правило целиком по записанным данным.
- **`runGatesAt`.** Именованные gates компонента (с предпосылками) на
  закреплённом SHA вне попытки — тем же путём, что интеграция задачи: свой
  worktree, снимки зависимостей, ресурсы, lifecycle и prepare, окружение
  интеграции, песочница проверок; каждый evidence — через callback хоста,
  первый провал останавливает прогон, дерево должно остаться прежним.
- **Учёт стоимости по всему потоку.** Адаптер CLI разбирает stdout по
  строкам по мере поступления и хранит только поля телеметрии (последний
  `result` claude, `turn.completed` codex, первая названная модель): цена
  длинного вызова больше не теряется за пределом хвоста вывода. Разбор
  ограничен по памяти и не бросает исключений из обработчика вывода.
- **Отчёт свойств в пробах ревьюера.** Проба gate получает путь отчёта
  свойств в scratch controller (`HARNESS_PROPERTY_REPORT`,
  `DEVCONTOUR_PROPERTY_REPORT` — та же переменная, что у движка) и сохраняет
  копию отчёта как evidence пробы; отчёт-ссылка отклоняется.

## Совместимость

Новые необязательные поля попытки (`interrupted`, `inputClasses`,
`classified`), поручения (`neutralFailures`), записи воспроизведения
(`inputClass`), evidence ревью (`alreadySatisfied`) и классы отказа
`unfinished` и `needs-lead`; в схемах данных CLI это единственные
аддитивные изменения перечней. Прежние записи не меняются.
Строгие схемы прежних версий новых значений не знают: после первой записи
alpha.17 откат — только через копию. Изменение поведения: тесты хоста,
ждавшие засчитанную попытку после отказа окружения или `failed` после
штатной остановки, нужно обновить. Матрица — [upgrade](../upgrade.md).

## Проверка выпуска

`npm run check` на macOS arm64, Node.js 24.3. Новые тесты на fixture runtime
и реальных Git-фикстурах (`repair`, `reproductions`, `runner` T14,
`explain-engine`, `network-recovery`, `reuse`, `usage`, `probe-gates`,
`already-satisfied`, `gates-at`); каждый новый тест обнаруживает свой мутант
реализации. Закрепление схем данных CLI (H3-01) сверяет байты H2 без
аддитивных значений `unfinished` и `needs-lead`. Живые модели не вызывались.
