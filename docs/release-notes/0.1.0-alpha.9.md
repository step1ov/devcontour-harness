# devcontour-harness 0.1.0-alpha.9

Нейтральное планирование для ведущего агента: проверяемый draft графа из
постановки и фактов проекта. План составляет сам ведущий агент — отдельная
модель-планировщик не вызывается. Gates, `maxAttempts`, бюджеты попыток и
повторов, правила находок, изоляция и принятие target ref не менялись.

## Что нового

- **`harness plan-request`** — запрос на план: `prompt`, `readOnly: true`,
  рекомендуемое и предельное число задач, факты проекта (`PlanningFacts`:
  репозитории, роли с `writePaths`, gates и группы, пакеты контекста, ресурсы,
  контракты с digest) и `basis` — digest постановки и фактов.
  `--requirements` добавляет снимок закоммиченных требований `## REQ-*` на
  `HEAD`. Только чтение: без runtime, state и записи.
- **`harness plan-check`** — проверка draft против фактов и сборка
  `WorkGraph`: `issues`, `checkPlan` (подготовка недостающих проверок), а без
  проблем — `graph`, `graphDigest` и `basis`. Неизвестные роли, gates,
  контракты и выдуманные digest требований — явные проблемы; ID и digest не
  подставляются, gates и требования не снижаются. Устаревшая постановка
  (`--basis`) или изменённое требование — `APPROVAL_STALE`. Draft ничего не
  согласовывает: лишние ключи (`approved`, `status`) отбрасываются,
  согласование — по-прежнему `review-plan` / `approve` / `run`.
- Схема `schemas/plan-draft.schema.json` и пример `templates/plan-draft.json`.
- Общие операции планирования для хостов: `planningRequest`,
  `planningBasis`, `planningFactsOf`, `standaloneInstructions`, `draftIssues`,
  `checkGaps`, `draftToGraph`, `planRequestOf`, `planCheck`;
  `validationIssues` — проверки `validateInputs` списком без исключения.
- Поставляемый skill и [standalone](../standalone.md) описывают маршрут
  `init → plan-request → draft → plan-check → validate → review-plan → run`.

## Изменения договора

Только добавления:

- CLI-команды `plan-request` и `plan-check` (`writes: false`), их схемы
  `data` в `cliDataSchemas`;
- публичная схема `plan-draft`;
- тип `CodedIssue` (`ErrorIssue` с кодом); `graphIssues` и `policyIssues`
  возвращают коды типа `ErrorCode` — значения прежние.

Прежние команды сохраняют конверт и exit codes.

## Совместимость

Формат состояния не менялся: alpha.9 читает всё, что читает alpha.8
([upgrade](../upgrade.md)).

## Проверка выпуска

`npm run check` (lint, typecheck, schemas, build, весь набор тестов, package
smoke с маршрутом из установленного архива) на macOS arm64, Node.js 24;
отдельный package consumer fixture проверяет операции планирования из
установленного архива. Ответы моделей в fixture-маршрутах запрограммированы:
это механика, не качество живого агента.
