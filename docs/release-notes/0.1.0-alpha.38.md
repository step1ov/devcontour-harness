# devcontour-harness 0.1.0-alpha.38

Вопрос исполнителя не тратит попытку. `stateVersion` и `policyVersion`
прежние.

## Изменения

- **Остановка вопросом.** Отказ `needs-input` возвращает попытку в предел
  `maxAttempts` и не тратит предел незасчитанных отказов. Ответ на вопрос,
  заданный на последней попытке, применяется (`applyInput`, `carryInput`)
  без `reset`; следующая выдача получает тот же номер попытки. Повтора без
  ответа по-прежнему нет: вопрос держит выдачу до применения.
- **Предел остановок вопросом.** Ответ может дать модель (режим `agent`),
  а отмена с повтором закрывает вопрос без ответа, поэтому возврат
  ограничен: поручение получает не больше `maxAttempts` остановок вопросом,
  возвращающих попытку, за всю жизнь; сброс попыток их не возвращает.
  Следующая остановка вопросом засчитывается как обычная попытка, и цикл
  «вопрос → ответ → применение» кончается исчерпанием попыток. Новой
  настройки нет: счёт ведётся по записям попыток.
- **События и отчёт.** `attempt.diagnosed` остановки вопросом пишет
  `counted: false`, сверх предела — `counted: true`. Отчёт считает
  засчитанные попытки по тому же правилу: остановка вопросом не засчитана,
  только если её `attempt.diagnosed` пишет `counted: false`. Остановку и её
  продолжение с тем же номером попытки различает `failureKind: needs-input`
  записи попытки.

## Обновление

Формат состояния прежний. Работы, остановленные вопросом до обновления,
хранят прежний счётчик попыток; их прежние остановки вопросом входят в
счёт предела. Подробнее — `docs/upgrade.md`.
