# devcontour-harness 0.1.0-alpha.24

Исправления выбора корня рабочих деревьев и диагностики после alpha.23.
Форматы состояния и политики, публичные поля API и обязательные проверки
приёмки не меняются.

## Изменения

- **Диагностика без записи.** `harness doctor` рассчитывает корень checkout,
  проверяет существующие каталоги и сообщает выбранное размещение, не
  создавая кэш, заданный корень или их родителей.
- **Отдельный корень.** Заданный `checkoutRoot` не может быть предком
  репозитория, каталога состояния или закрытого пути. Как прежде, он не
  может лежать внутри них. Символическая ссылка вместо заданного корня и
  ошибки чтения его метаданных отклоняются; отсутствие каталога допустимо.
- **Права и отсутствующий кэш.** Новый корень и недостающие родители
  создаются с mode 0700, включая заданный хостом корень. На Linux отсутствие
  `~/.cache` больше не возвращает рабочие деревья внутрь репозитория;
  недостающие каталоги кэша создаются. Права существующих каталогов
  пользователя не меняются.
- **Класс отказа чтения.** Учётные данные исключены из перевода отказа в
  `environment`: чтение `~/.npmrc`, `~/.netrc` и других защищённых путей
  остаётся ошибкой gate, даже если путь лежит в предке cwd и журнал ядра
  подтверждает отказ. Это не меняет само запрещение чтения.

## Совместимость и ограничения

Для обновления и отката применяются прежние правила `engineVersion`:
остановить writers, сохранить копию состояния, проверить её новой версией
и возобновить одним controller. Состояние не преобразуется; alpha.23
читает записи alpha.24. Хостам с корнем-предком или ссылкой вместо корня
нужно указать отдельный каталог. Матрица — [обновление](../upgrade.md).

Содержимое соседних рабочих деревьев закрыто песочницей. На macOS различие
ENOENT и EPERM может раскрыть существование пути; скрытие имён или самого
факта существования не гарантируется. Проверка ОС выполняется на macOS;
Linux-выбор корня покрывается проверками путей и файловой системы, без
заявления о запуске Linux-песочницы.

## Проверки

CR14 проверяет исключение всех известных путей учётных данных из класса
`environment`; CR15 — корни-предки, создание с mode 0700 и отказ по ссылке;
CR16 — создание отсутствующих родителей кэша и выбор без записи на macOS
и Linux. Тест doctor проверяет отсутствие новых файлов и каталогов после
диагностики кэша и явно заданного корня. Прежние CR01–CR13 проверяют
изолированные Git-деревья, gates обеих фаз, проверку на SHA, перенос базы
и закрытие соседней попытки. Выпускной маршрут — `npm run check`, включая
установку архива и цикл на fixture runtime; живые модели для него не нужны.
