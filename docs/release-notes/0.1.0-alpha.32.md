# devcontour-harness 0.1.0-alpha.32

Хост строит пакет передачи контекста над своим движком без экземпляра
`Harness` и под свой предел ответа, а проверки в песочнице стартуют и при
глубоком TMPDIR. Форматы состояния, политики, событий и `HandoffPack`
прежние.

## Изменения

- **Пакет передачи для хоста.** `handoffPack(source, options)` принимает
  `HandoffSource` (`{ engine, policy, workflows }`); `Harness` ему
  удовлетворяет. `statusOf(source, graphId?, { detail })` — состояние доски
  над движком и политикой. Параметры `maxBytes` (от 4096 байт до 256 КБ) и
  `measure` (`json` | `markdown`) подгоняют пакет тем же порядком
  отбрасывания под меньший предел; `truncated.bySize` значит «записи
  отброшены», размер результата хост проверяет сам.
- **Экспорты из корня пакета.** `policySecrets` (секреты политики для маски
  хоста), `writeReportFile`, `REPORT_FILE_MODE`, `ReportFileIo` (запись
  отчёта, как у `harness report --out`), `HANDOFF_MIN_BYTES`.
  `devcontour-harness/report` по-прежнему без `node:*`.
- **Песочница при глубоком TMPDIR.** Когда путь unix-сокета sandbox-runtime
  не помещается в предел ОС (104 байта на macOS, 108 на Linux), srt получает
  короткий каталог `/tmp/dc-srt-<pid>-*` с правами `0700`, который
  удаляется после проверки. Брошенные каталоги этого пользователя, где ничего
  не менялось больше суток и создателя нет, убираются при создании нового.
  Если короткий каталог недоступен — отказ среды с TMPDIR в тексте. Раньше
  проверка падала с `listen EINVAL` и не считалась отказом среды.
- Строка Markdown об урезании пакета — «Пакет урезан по пределу размера».

## Обновление

Пакет alpha.31 остаётся неизменным. Состояние и политика не меняются, откат
копии не требует. Подробнее — `docs/upgrade.md`.
