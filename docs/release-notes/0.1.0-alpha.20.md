# devcontour-harness 0.1.0-alpha.20

Исправление containment на машинах с неанглийской локалью. Включает всё из
[0.1.0-alpha.19](0.1.0-alpha.19.md). Формат состояния, gates, правила
находок, изоляция, принятие target ref и `maxAttempts` не менялись.

## Что исправлено

- **Потомок проверки не переживает её при любой локали.** Ядро находит
  отсоединившегося потомка с очищенным окружением по текущему каталогу внутри
  каталогов проверки и отсекает процессы старше команды по времени старта из
  `ps -o lstart=`. Утилиты наследовали локаль пользователя: в `ru_RU.UTF-8`
  `ps` печатает «среда, 28 октября 2026 г. 16:42:10», `Date.parse` его не
  читает, и такой потомок считался старше команды и оставался жить. Теперь
  каждая системная утилита, чей вывод разбирается (`ps`, `lsof`, `sysctl`,
  `ps` ревью-зонда), запускается с `LC_TIME`, `LC_NUMERIC` и `LC_MESSAGES` в
  локали C (`osToolEnv`).
- **Кириллица в пути каталога.** `LC_ALL=C` не подходит: в локали C `lsof`
  экранирует байты не-ASCII путей (`\xd0\xbb…`), и каталог с кириллицей не
  узнавался. Кодировка символов остаётся пользовательской (значение `LC_ALL`
  переносится в `LC_CTYPE`), а экранирование `lsof` снимается (`lsofName`),
  если локаль пользователя сама C.
- **Нечитаемое время старта — не исключение.** Процесс с текущим каталогом
  внутри каталогов проверки, время старта которого не прочитано,
  останавливается: эти каталоги принадлежат только проверке. Не
  останавливается только процесс, о котором точно известно, что он старше
  команды (например, терминал, открытый в worktree раньше), и процесс, которого
  нет в снимке таблицы процессов (в их числе сам `lsof`).

## Совместимость

Формат состояния и публичный API не меняются (`osToolEnv` и `lsofName` —
внутренние). Матрица — [upgrade](../upgrade.md).

## Проверка выпуска

Новый тест `process` T30 воспроизводит потомка с очищенным окружением при
локали `ru_RU.UTF-8` и при локали C с кириллицей в имени каталога: на
alpha.19 он оставался жив, мутанты без фиксированной локали и без снятия
экранирования `lsof` тест обнаруживает. Модульный тест `os-tools` проверяет
окружение утилит и снятие экранирования. Полный `npm run check`.
Живые модели не вызывались.
