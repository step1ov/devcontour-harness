# devcontour-harness 0.1.0-alpha.58 (не выпущен)

Черновик. `stateVersion`, `policyVersion`, `handoffVersion`, `reportVersion`
и `viewVersion` прежние; `viewRevision` — `2`. Схемы JSON не меняются.

## Изменения

### Порядок заданий технической очереди не зависит от часов

Задание `workflow-jobs` получает при постановке номер `seq` — следующий
после наибольшего в хранилище; номер хранится в записи и переживает
перезапуск. `WorkflowQueue.list()` отдаёт задания от старых к новым по
номеру (раньше — по ключу-digest), `newestWorkflowJob` возвращает новейшее,
`compareWorkflowJobs` — порядок. Равное или откатившееся `startedAt` больше
не выбирает новейшее задание по произвольному ключу. Задания прежних версий
без `seq` читаются без миграции: они старше любого задания с номером, между
собой — по времени `startedAt`, затем по ключу. `repairs[]` пакета передачи
сначала перечисляет действующие задания (не `stale` и не замещённые более
новым заданием того же графа), затем устаревшие, внутри группы — новые
первыми: при пределе 10 действующее задание любого графа не вытесняется
историей устаревших.

### Строка попыток сохраняет требуемое действие

`attempts.line` в пределе длины (200 символов у `harness view`, 1000 у
`status`) больше не теряет хвост «повтор — только со сбросом» (`retry only
after a reset`) и остаток попыток при длинном списке отказов: сначала
список сокращается до первых корзин и «и ещё N» (`and N more`), затем
начало строки. Строку собирает новая функция `attemptLine`
(`devcontour-harness/projections`); `attemptSummaryLine` принимает
необязательные `lang` и `max`.

## Обновление и откат

См. `docs/upgrade.md`, раздел 0.1.0-alpha.58: откат на alpha.57 после
постановки нового задания очереди — через копию состояния (строгая схема
alpha.57 не знает `seq`).
