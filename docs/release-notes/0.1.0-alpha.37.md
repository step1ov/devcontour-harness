# devcontour-harness 0.1.0-alpha.37

Вопрос исполнителя: writer останавливается на развилке, ответ проходит ревью
контекста и применяется к следующей попытке. Диагностика остановок для многих
работ за одно чтение. `stateVersion` и `policyVersion` прежние.

## Изменения

- **Вопрос исполнителя.** Необязательные `inputRequest` и `assumptions` в
  ответе writer, политика `inputPolicy {threshold 1–11, criticalPaths}`
  (порог по умолчанию 7, 11 — автономный режим), локальное пространство
  `input-requests`, класс отказа `needs-input` и код `INPUT_REQUIRED`.
  Ответ, снимок контекста с ответом, его ревью, применение, замена и перенос
  ответа в новую редакцию; команды CLI `input-*`; необязательный порт
  `ExecutionHost.input`. Подробно — `docs/contracts.md#вопрос-исполнителя`.
- **Диагностика многих работ.** `stopInputsOf(source, { maxAttempts,
repairBudget, workIds })`: каждая работа из `workIds` получает то же, что
  вызов с её `workId`, в порядке состояния; неизвестный ID — `NOT_FOUND`,
  `workId` вместе с `workIds` — `INVALID_INPUT`. Вызов для всей доски и для
  набора читает общие данные один раз и линеен по числу работ и связей.
- **Помощники движка** (каждый действителен только внутри своего чтения):
  `Engine.approvalStaleness(view)`, `Engine.budgetBlockers(view)`,
  `Engine.budgetBlocksOf(workIds | undefined, view)` — блокировки бюджета
  набора работ за одно чтение, значение равно `budgetBlockOf(workId, view)`.
  Необязательные `records` у `budgetBlockOf` и `blocking` у `repairDecision`.
- **Перенос ответа.** Снятие устаревшего перенесённого ответа сохраняет
  запись замены в `closed.previous`.
- **Объяснение.** Работа, отказавшая до старта (не засчитанная попытка,
  например без закреплённого снимка контекста), объясняется фазой `preflight`;
  `StopInput.work.preflight` — новое поле. Класс отказа `needs-lead` и его
  правила прежние.
- **Отчёт.** `report.inputs.carryStale` считает вопросы с устаревшим
  перенесённым ответом; `report.inputs.closed` их больше не считает.

## Обновление

Новое аддитивно; схемы прежних версий не принимают новые необязательные поля
(`inputPolicy`, `closed.previous`, `inputs.carryStale`): при откате уберите
их или восстановите копию каталога состояния, снятую до обновления.
Подробнее — `docs/upgrade.md`.
