# devcontour-harness 0.1.0-alpha.55 (черновик)

## Изменения

### Представление оператора: `harness view`

- **Новая команда** `harness view --state D [--policy F] [--work ID]
[--no-titles] [--window 24h|7d] [--bucket 15m|1h] [--lang ru|en]
[--view-version 1]` — один JSON-документ только для чтения для панели
  оператора (`OperatorView`, с `--work` — `WorkDetailView`). Документ
  несёт `viewVersion: 1` и `viewRevision: 0`; схемы —
  `schemas/operator-view.schema.json` и `schemas/work-detail-view.schema.json`.
  Команда есть в `capabilities` (`readOnly: true`); операция библиотеки —
  `harnessView(options)`.
- **Чистая проекция** `operatorView(input, options)` и
  `workDetailView(input, workId, options)` в `devcontour-harness/projections`
  (без `node:*` и zod) и загрузчик `collectOperatorViewInput` для node. Числа
  — те же, что у `status` и `report`: проекция их не выводит заново.
- **Маскирование до обрезки** каждого свободного текста
  (`maskText`, `redactThenClip` теперь и в `./projections`), пределы
  списков с `truncated` и отказ `VIEW_TOO_LARGE` для документа больше
  256 КБ, токен содержимого `source.token` (SHA-256 без `generatedAt`).
- **Язык** простых строк harness — `--lang ru|en` (по умолчанию `ru`).
- **Коды ошибок.** `POLICY_REQUIRED` (exit 2): нет состояния и нет
  `--policy`. `VIEW_TOO_LARGE` (exit 4).

## Совместимость

- Команда, схемы и коды ошибок — аддитивны; прежние команды не меняются.
- `harness view` читает состояние неизменяемым открытием, как `report`: без
  журнала WAL в каталоге состояния не появляется ни одного файла; при идущем
  `run` SQLite может создать служебный `-shm`, как у `status`.
- Несовместимое состояние даёт `STATE_VERSION_UNSUPPORTED` (exit 4), как у
  остальных читающих команд.
