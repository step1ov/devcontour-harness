# devcontour-harness 0.1.0-alpha.55

Черновик. `stateVersion`, `policyVersion`, `handoffVersion` и
`reportVersion` прежние: изменения схем аддитивны (необязательные поля),
записи состояния не меняются.

## Изменения

### Почему повтор, почему не выдаётся, что проверено и как

Оператор видит прогресс простыми словами, без пересказа ведущего агента.

- **Почему поручение повторяется.** Строка этапа `status`
  (`works[].stage.line`, `lineEn`) называет номер попытки из предела и
  причину остановки прошлой попытки: «попытка 3 из 6; прошлая остановлена:
  окружение — порт 3000 занят»; у ждущей и остановленной — «попыток
  использовано 3 из 6; последняя остановлена: дефект — не прошли проверки:
  unit». Сводка попыток `status` и `explain` — поле `lastFailure` (`runId`,
  корзина, класс, время, `plain`/`plainEn`). Текст строится из класса
  отказа, ID упавших gates и номера занятого порта: свободный текст ошибки
  в него не попадает.
- **Почему не выдаётся.** У каждой блокировки `status`
  (`works[].blockers[]`) — простой текст по-русски и по-английски и кто её
  снимает (`plain`, `plainEn`, `actor`): «ждёт зависимости a», «черновик —
  не утверждён», «ждёт согласования плана», «ждёт вашего ответа на вопрос
  исполнителя», «пауза очереди: бюджет». Ждущее выдачи без блокировок —
  «просто ждёт очереди — ничего не нужно». `status --human` печатает
  блокировки простым текстом, коды — в скобках. У каждого кода
  `Engine.blockers` есть текст: тест падает, если код добавлен без него.
- **Что проверено и как.** `status`, `explain`, `result`/`deliver` и отчёт
  несут `verification`: строку на gate и ревью попытки (записи текущего SHA
  фазы) — `result` (`passed`, `failed`, `reused`, `skipped`,
  `not-applicable`) и `how` (`executed-by-harness`, `reused-evidence`,
  `read-by-reviewer`, `not-run`), у ревью — runtime и вендор reviewer, что он
  запускал по записи controller и протокол ответа — и одну строку:
  «Проверено harness (запущено): lint, unit; ревью: прочитал агент openai
  (codex), только diff, ничего не запускал — одобрил; не проверялось: e2e
  (изменения его не задели)». Gate, который песочница не запустила, — «не
  запустилась — отказ среды», а не «не прошло». Только ID gates, без
  команд. Текст для человека не говорит «проверено» или "checked" без того,
  кто и как проверял. В отчёте проверки поручений держат общий предел 64 КБ.
- **Библиотека.** `plainBlocker`, `blockerCodeText`, `failurePlainOf`,
  `verificationOf`, `verificationRows`, `verificationLines`, схема
  `workVerificationSchema`.

## Совместимость и откат

- Новые поля ответов необязательны: `attemptSummary.lastFailure`,
  `works[].blockers[].plain/plainEn/actor`, `works[].verification`,
  `explain.verification`, `result.verification`,
  `works.rows[].verification` отчёта. Потребитель со строгой схемой прежней
  версии должен их принять.
- Текст `status --human` и `explain --human` изменился (строка блокировок,
  строка `проверки:`, этап `queued`, раздел проверок `explain`); скрипты
  читают JSON.
- Откат на 0.1.0-alpha.54 не требует действий с данными.

## Проверка

Новые тесты: `tests/plain-progress.test.ts` (строка этапа с причиной
повтора, `lastFailure` без свободного текста ошибки, текст и актёр каждого
кода `Engine.blockers`, разновидности блокировок, строки и сводка проверки,
одна проверка в `status`, `explain`, `result` и отчёте, сканирование текста
для человека). Живые модели не вызывались.
