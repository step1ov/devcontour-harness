# devcontour-harness 0.1.0-alpha.51

Выпуск собирает пять изменений: команду `harness lean` для
подготовленного проекта, ещё один запуск повтора интеграции после падения
исполнителя тестов, срок слоя `lean` как нижнюю границу, предупреждения в
ответе `harness gates` и заметку о параметрах библиотечного `doctor()`. `stateVersion`, `policyVersion` и
`manifestVersion` прежние; политики и manifest не переписываются, пока не
вызвана `harness lean`.

## Изменения

- **`harness lean --repository <repo> [--state D] [--off] [--plan] [--human]`.**
  Включает и выключает слой `lean` в проекте, подготовленном `init`, вместо
  ручной правки `.harness/policy.json`. Включение складывает `concurrency`,
  `runTimeoutMs` и `gateTimeoutFloorMs` со слоем (наименьшая параллельность,
  наибольшие пределы, срок не меньше требуемого пределами шагов), добавляет
  `dependencyStore` pnpm-профилю с `pnpm-lock.yaml` и записывает в manifest
  `profile.layers` и прежние значения (поле `lean`); `--off` возвращает их
  точно. `--plan` ничего не пишет, `--state` задаёт каталог состояния для
  проверки идущего run (`CONTROLLER_BUSY`). Поле, изменённое вручную после
  включения, — `PATH_CONFLICT`; файл, изменённый между чтением и записью, —
  `REVISION_CONFLICT`. Каждый файл заменяется атомарно, два вместе — нет:
  половину переключения дописывает повтор, а `doctor` показывает её новым
  предупреждением `LEAN_MISMATCH`. Библиотека: `switchLean`.
- **Советы `doctor`.** `LOW_RESOURCES` и `DEPENDENCY_STORE_RECOMMENDED` для
  политики в `.harness/` называют `harness lean --repository <корень> --plan`
  вместо списка полей; для политики вне проекта совет начинается с полей.
- **Повтор после падения исполнителя тестов (F68).** Повтор gate на
  integration, который прошёл все прежде упавшие тесты и провалился только
  ненулевым кодом выхода исполнителя тестов (полный отчёт без упавших
  тестов, без отчёта свойств), получает ещё один запуск на том же
  integration SHA; его исход решает, засчитывается ли провал. Лог и отчёт —
  в собственном каталоге `integration/recheck-2/`, лог упавшего повтора
  остаётся при своём digest. Срок фазы интеграции (`phaseBudgets`,
  `requiredRunTimeoutMs`) учитывает этот запуск ещё одним пределом самого
  долгого gate; отчёт об эффекте считает один, последний исход на
  повторённую запись. Таймаут, исполнитель, убитый сигналом, и неостановленные
  потомки не продлеваются.
- **Срок слоя `lean` — нижняя граница.** `runTimeoutMs` профиля или слоя
  больше не предел вывода: требуемый пределами шагов с запасом (×1.25, вверх
  до 5 минут) пишется, как только он больше срока слоя, а не только когда
  политика со слоем получила бы предупреждение. `init --lean` и
  `harness lean` дают один срок, не меньше 30 минут и не меньше, чем `init`
  без слоя (`npm-ci`, `pnpm-frozen` — 2100000, `mobile-maestro` — 3000000).
  Политику прежнего `init --lean` со сроком 1800000 `doctor` не считает
  ручной правкой; `harness lean` её поднимает, `--off` возвращает срок без
  слоя.
- **`harness gates`: предупреждения.** Ответ несёт необязательное поле
  `warnings` (предупреждения пробы портов из `GatesAtResult.warnings`:
  порт на всех адресах держит чужой процесс при свободном loopback);
  `--human` печатает их строками `предупреждение: …`.
- **`docs/upgrade.md`.** Раздел 0.1.0-alpha.50 называет необязательный шестой
  параметр библиотечного `doctor()` —
  `options: { resourceDatabase?: string | false; planAuthors? }`. Раздел
  «Следующий выпуск» переименован в «0.1.0-alpha.51».

## Совместимость

- Строгая схема manifest прежних версий не принимает поле `lean`: перед
  откатом выполните `harness lean --repository <repo> --off` или удалите
  локальный `.harness/project.json` и выполните `init` прежней версией.
  Подробности — [upgrade](../upgrade.md).
- Digest политики меняется при каждом переключении `harness lean`:
  согласованные под прежней политикой графы получают `APPROVAL_STALE`.
- Срок, который `init` и `harness lean` выводят из пределов шагов
  (`requiredRunTimeoutMs`), может вырасти на предел самого долгого gate из-за
  дополнительного запуска повтора интеграции, а для слоя `lean` — потому что
  его срок стал нижней границей; уже записанные политики не переписываются.
