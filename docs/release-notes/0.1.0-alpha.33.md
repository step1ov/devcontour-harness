# devcontour-harness 0.1.0-alpha.33

Пакет передачи и `explain` на долгой истории больше не начинают с ложных
решений: отменённая работа — решение ведущего, только пока от неё ждёт
незавершённая работа, а расход ревью плана не повторяется строкой у каждого
поручения. Форматы состояния, политики и событий прежние; `handoffVersion` — 1.

## Изменения

- **Отменённые без ждущих.** `CANCELLED` → `replan-dependents` только при
  прямо зависящей незавершённой работе, сообщение называет ждущих. Без них
  отменённая работа в общий `explain` и в `stops`/`next` пакета не входит;
  `explain --work` показывает её с `action: none`.
- **Упавшая с классом `cancelled`.** Движок её не повторяет, поэтому без
  ждущих это решение человека: `harness retry` или отмена (`user-decision`,
  `nextAction` — шаг `cancelled`), а не «повтор в пределах бюджета».
- **Группа без восстановления из-за отмены.** Диагноз упавшей работы называет
  отменённую, из-за которой движок не восстанавливает группу.
- **Бюджеты в пакете передачи.** Вызов о группе (ревью и проверка плана)
  по-прежнему засчитывается бюджету каждого открытого поручения группы, но
  строки поручений, весь расход которых — такие вызовы и которые выдачу не
  держат, в пакет не входят; их число — `truncated.budgetsShared` (по
  умолчанию 0). Блокирующие строки остаются.

## Обновление

Пакет alpha.32 остаётся неизменным. Состояние не меняется, откат копии не
требует. Внешний валидатор со строгой прежней схемой пакета передачи
обновляется вместе с harness. Подробнее — `docs/upgrade.md`.
