# devcontour-harness 0.1.0-alpha.29

Проверки в песочнице ОС больше не срываются под нагрузкой машины, а копия
хранилища зависимостей готовится примерно в 4 раза быстрее. Обязательные gates,
fencing, привязка доказательств к SHA и граница доверия хранилища не меняются.

## Изменения

- **Старт песочницы под нагрузкой.** sandbox-runtime искал shell через `which`
  с таймаутом в секунду на каждый запуск; под нагрузкой проверка не стартовала
  с ошибкой «Shell 'bash' not found in PATH», похожей на провал проекта. Теперь
  shell находится без дочернего процесса и только в абсолютных каталогах PATH.
- **Доказанный старт.** Обёртка печатает в stderr случайный токен перед `exec`;
  он ищется в сыром потоке до маски секретов. Команда, стёршая свою метку
  старта, больше не считается не запущенной и не повторяется.
- **Отказ среды вместо провала проекта.** Если песочница так и не запустила
  команду, а stderr состоит только из известных строк отказа запуска, gate
  получает класс `environment` с понятным сообщением; probe reviewer —
  `error`/`environment`. Прочие отказы до старта остаются провалом проверки.
  На Linux классификация не проверялась.
- **Хранилище зависимостей быстрее.** На macOS копия seed делается одним
  `clonefile(2)` каталога (при отказе — прежними порциями `cp -c`), байты и права
  копии сверяются с закреплённым манифестом в пуле потоков. Seed 433 МБ /
  36 690 файлов: подготовка копии 2,35 с вместо 9,2 с.
- **Новый отказ.** Файл seed с setuid, setgid или sticky отклоняется (pnpm таких
  не создаёт); удаление копий снимает BSD-флаги вроде `uchg`.

## Обновление

Пакет alpha.28 остаётся неизменным. Форматы состояния, политики и манифест seed
прежние; seeds и копии подходят обеим версиям. Откат возвращает прежний поиск
shell и прежнюю классификацию отказов запуска (`gate`).
