# devcontour-harness 0.1.0-alpha.61 (черновик, не выпущен)

`stateVersion`, `policyVersion`, `handoffVersion`, `reportVersion` и
`viewVersion` прежние; `viewRevision` — 4. Схемы JSON расширены совместимо:
`ControlState.pauseOwner`, ключи `truncated.workFields` и `truncated.whatsNew`
представления оператора. Порядок обновления и отката — `docs/upgrade.md`,
раздел alpha.61.

Выпуск закрывает хвосты alpha.60: представление оператора больше не
отказывает целиком из-за размера, пауза убитого обновления не держит очередь
вечно, а записи библиотеки во время обновления отказывают так же, как
команды CLI.

## Изменения

### Представление оператора

- Документ больше 256 КБ теряет необязательное в одном порядке: разделы
  связки, поля ревизии 4 у работ (`truncated.workFields`), ленту, затем хвосты
  списков одной долей — с числом опущенного в `truncated` и предупреждением
  `VIEW_SIZE_REDUCED`. Типичный документ на 500 работ с полями ревизии 4 у
  всех и дрейфом у 50 выдаётся, а не отказывает `VIEW_TOO_LARGE`.
- Пункты `updates.whatsNew` сверх 10 считаются в `truncated.whatsNew`; раздел
  `updates` остаётся при `VIEW_SECTIONS_DROPPED`.
- Строка прогноза: «ждут людей сейчас: N, меньше минуты» вместо «до меньше
  минуты».

### `harness update`

- Пауза обновления помнит процесс (pid и момент старта). Обновление, убитое
  до изменений (во время `--wait`), больше не держит `run`, регистрацию и
  совместную проверку: `run` снимает такую паузу, `status --detail` объясняет
  её. Незавершённый возврат по-прежнему держит всё до `harness update --check`.
- Записи библиотеки (`Harness.resolveInput`, `Harness.carryInputOf`, ответы,
  перенос и закрытие вопросов, `acceptCodeFindings`, `retry`, `cancel`)
  отказывают `CONTROLLER_BUSY`, пока обновление держит состояние, — как
  команды CLI.
- `status` с неверным `.harness/updates.json` не печатает «Обновления:
  <ошибка>»: настройка пропускается с одним предупреждением на stderr.

### Проверка репозитория

- `DS42` находит pnpm 11 в кэше npx, если его нет в PATH и не задан
  `HARNESS_TEST_PNPM11_DIR`; пропуск остаётся ошибкой полного прогона.
- `T05` восстанавливает права каталога, закрытого исполнителем (mode 0):
  уборка каталога прогона больше не оставляет его и не печатает
  «Run directory not removed … ENOTEMPTY».

## Известные ограничения

- Рабочее дерево попытки, в котором исполнитель закрыл каталог (mode 0),
  уборка harness удаляет не полностью (`git worktree remove --force` не
  меняет права) — остаётся до ручной уборки.
