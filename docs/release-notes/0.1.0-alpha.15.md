# devcontour-harness 0.1.0-alpha.15

Защита эталонной проверки от подгонки под наборы, закреплённые файлы сверки
эталона и ID testcase node:test. Включает всё из
[0.1.0-alpha.14](0.1.0-alpha.14.md): alpha.14 — локальный выпуск, в npm не
публиковался; первая публикуемая версия с эталонными наборами — alpha.15.
Gates, `maxAttempts`, бюджеты попыток и повторов, правила находок, изоляция,
принятие target ref и формат состояния не менялись.

## Что нового

- **Ответы наборов не подсказка реализации.** Writer и reviewer кода получают
  список файлов эталонных наборов поручения. Для reviewer чтение их из кода
  реализации, вшитые ответы и особые случаи для входов наборов — блокирующая
  находка. Controller отклоняет кандидата до gates (`scope-violation`
  «Реализация ссылается на файлы эталонных наборов»), если изменённый файл
  содержит путь или имя файла набора. Имя, собранное во время исполнения, и
  копия ответов без имени файла механически не ловятся — их ловит ревью кода
  ([договор](../contracts.md#способы-исполнения-обязательства-property-и-reference)).
- **`crossChecks[].artifacts`.** Сверка эталона может ссылаться на
  закреплённый скрипт или журнал, который её воспроизводит; файлы обязаны
  быть артефактами контракта. Reviewer контракта оценивает сверку без них
  как непроверенное утверждение автора.
- **Мёртвые обязательства.** Обязательство `property` любого обещания на
  gate без `property` отклоняется до вызова модели: поручение его выбрать не
  может. Прежде так отклонялись только вычислительные обещания.
- **ID testcase.** Отказ «testcase X отсутствует в JUnit» называет найденный
  `<classname>.X` (node:test пишет `classname="test"`, и ID свойства для него
  — `test.<имя теста>`); правило описано в
  [договоре](../contracts.md#id-testcase-и-отчёта).
- Сообщение отказа gate, где генеративные и эталонные свойства вместе:
  «Проверка свойств и эталонных наборов …».
- `gates` обязательства, равные `checks.gate`, дают то же основание корпуса,
  что и без поля.

## Изменения договора

Добавления: `reference.crossChecks[].artifacts` (1–10 путей), экспорты
`referenceSetFiles` и `referenceCodeNote`. Изменение отказа: обязательство
`property` с необязательным обещанием (`functional`, `invariant`, `other`) на
gate без `property` теперь — структурный отказ договора (текст «… не
генеративный (нет property) — поручение не сможет выбрать это свойство; …»;
у вычислительных обещаний текст тоже дополнен). Договор без новых полей даёт
тот же манифест, digest и основание корпуса.

## Совместимость

Формат состояния тот же. Договор с новыми полями alpha.13 и раньше не
принимают (строгая схема). Обновление и откат — по [upgrade](../upgrade.md).

## Проверка выпуска

`npm run check` на macOS arm64, Node.js 24.3. `tests/reference.test.ts`
(14 тестов): к проверкам alpha.14 добавлены отказ кандидата, читающего файл
набора, список наборов в запросах writer и reviewer, testcase с другим ID,
настоящий JUnit node:test (`test.<имя>`), файлы сверки, мёртвое
обязательство-инвариант, основание корпуса при `gates` равных gate договора.
Каждая новая проверка падает на своём мутанте (29 из 29). Живые модели не
вызывались.
