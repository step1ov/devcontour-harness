# devcontour-harness 0.1.0-alpha.12

Skill установки, первой настройки и обновления версии. Движок, CLI, договоры
`v1alpha1`, политика, профили и формат состояния не менялись; gates,
`maxAttempts`, бюджеты попыток и повторов, правила находок, изоляция и
принятие target ref — прежние.

## Что нового

- **`skills/harness-setup/SKILL.md`** — маршрут для агента пользователя:
  - один раунд вопросов: существующий или новый проект, ветка подготовки,
    каталог установки (`.harness-tools/` внутри проекта или каталог
    снаружи), источник пакета (npm `@alpha`, сведённый к точной версии,
    точная версия или архив с sha256), writer и reviewer, модели и effort,
    ревью тем же вендором (только явным «да»), режим согласования плана,
    источник задач (файлы графа, Relay v1, Relay-2), коммит подготовки;
  - новый проект: Git, `package.json` со scripts `check` и `test` (JUnit в
    `.reports/junit.xml`) и lockfile — только с согласия пользователя;
  - установка в проект: версию закрепляют `.harness-tools/package.json` и
    `package-lock.json`, `node_modules/` не коммитится, каталог добавляется в
    `protectedPaths` политики; из архива — каталог целиком в
    `.git/info/exclude`;
  - `init` и правки политики по ответам: `model`, `effort` (только для
    codex), reviewer того же вендора для ревью кода и контракта
    (`same-vendor-allowed`), `approvalMode`; проверка `doctor --policy`
    (схема, runtime, toolchain), `init --plan` без конфликтов и `validate`
    первого графа (перекрёстные проверки политики);
  - `connector.json` для Relay и проверки без записи в Relay
    (`source-check`, `source-snapshot`);
  - обновление: остановка writers, копия state, проверка копии новой
    версией, установка, `doctor --state`, `init --plan` (изменённый профиль,
    перенос репозитория или версия API — решение человека; manifest
    пересоздаётся с прежним state, политика не перегенерируется), `validate`
    графов, `resume`; откат по [upgrade](../upgrade.md);
  - восстановление закреплённой версии в новом клоне — `npm ci --prefix
.harness-tools`.
- `skills/harness/SKILL.md` по-прежнему ведёт работу с поручениями; новый
  skill передаёт ему управление после подготовки. В нём уточнены каталог
  установки (снаружи или `.harness-tools/`) и причины `content-differs` на
  `project.json` после обновления или переноса.

## Совместимость

Формат состояния не менялся: alpha.12 читает всё, что читает alpha.11, а
alpha.11 — всё, что пишет alpha.12. Обновление и откат — по
[upgrade](../upgrade.md).

## Проверка выпуска

`npm run check` (lint, typecheck, schemas, build, весь набор тестов, package
smoke из установленного архива) на macOS arm64, Node.js 24.3. Тест skill
сверяет с договором CLI каждую команду маршрута: команду, флаги и
обязательные аргументы полных вызовов; smoke установленного архива требует
оба skill. Маршрут установки в `.harness-tools/` пройден вручную на свежем
npm-репозитории с опубликованной alpha.11: `init --plan`, `init`, правки
политики, `doctor --policy`, отказ `validate` для `effort` не у codex,
пересоздание manifest с прежним state. Живые модели не вызывались;
проверка DevContour для alpha.12 не повторялась (движок не менялся,
[проверенные версии](../compatibility-versions.md) относятся к alpha.11).
