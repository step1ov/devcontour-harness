# devcontour-harness 0.1.0-alpha.22

Ужесточение сверки защищённых путей вокруг исполнителя и gates. Включает всё из
[0.1.0-alpha.21](0.1.0-alpha.21.md). Формат состояния, gates, правила находок,
принятие target ref и `maxAttempts` не менялись.

## Что исправлено

- **Имена без регистра.** На нечувствительной к регистру ФС (APFS по
  умолчанию, NTFS) `.Claude/settings.json`, `.VSCode/tasks.json`, вложенный
  `sub/.GIT` или `.Bashrc` хост читает как имена нижнего регистра, а сверка
  сравнивала имена точно и их пропускала. Теперь защищённые имена сравниваются
  без регистра на любой платформе; на чувствительной к регистру ФС такое имя
  тоже нарушение — создавать его незачем. Отказ обязательного запрета из
  журнала ядра узнаётся в любом регистре (`.IDEA/x` — «каталог IDE .idea»).
  Запреты записи sandbox-runtime менять не потребовалось: проба под песочницей
  на APFS показала, что Seatbelt сам отказывает в `.IDEA/x`, `.VSCode/x`,
  `.Bashrc`, `.Claude/commands/x` и `x/.GIT/hooks/x`.
- **Непрочитанный путь — отказ, а не пропуск.** Ошибка `lstat`, `readdir` или
  `readlink`, кроме ENOENT, раньше превращалась в «пути нет»: `chmod 0444 sub`
  прятал `sub/.claude/settings.json`, каталог без права чтения не
  перечислялся. Теперь это отказ сверки с путём и кодом ошибки в сообщении
  («нет доступа к sub/.claude (EACCES)»), и так же для пустого `.claude` с
  правами 000. До работы исполнителя или gate — класс `environment`; после —
  `scope-violation`.
- **Открытые каталоги не пустые.** Пустое дерево каталогов (служебный
  `.claude/.cc-writes`) по-прежнему не нарушение, только если ни один каталог
  в нём не открыт на запись группе или всем (`mode & 0o022`). Подпись каталога
  несёт права: смена прав защищённого каталога с файлами — тоже изменение.
  FIFO, сокет и прочие не-каталоги внутри — содержимое, а не пустое дерево.

## Совместимость

Формат состояния и публичный API не меняются. Матрица —
[upgrade](../upgrade.md). Каталог checkout, который нельзя прочитать (вне
`node_modules`), теперь останавливает gate с классом `environment` вместо
молчаливого пропуска. При umask, открывающем каталоги группе (`002`), CLI
исполнителя создаёт `.claude` с правами 775 — такой каталог теперь нарушение.

## Проверка выпуска

Тесты `sandbox-install`: SBX06 — FIFO в `.claude/.cc-writes` нарушение; SBX08 —
`.Claude`, `.VSCode`, вложенный `.GIT`, `.Bashrc`, `.MCP.json` нарушение,
пустой `.CLAUDE/.cc-writes` — нет, обязательный запрет узнаётся в любом
регистре; SBX09 — каталог без права поиска, неперечисляемый каталог и `.claude`
с правами 000 — отказ с путём; SBX10 — пустой каталог 777/775/757 и смена прав
каталога с файлами — нарушение; SBX11 под песочницей ОС — `.IDEA` закрыт ядром,
`.Claude/settings.json` в существующий `.claude` и спрятанный `chmod`
`sub/.claude` — `scope-violation`. Тест `runner` T05 под песочницей ОС:
`.Claude/settings.json`, `.cc-writes` с правами 777 и `src/.claude` с правами
000 — `scope-violation`. Мутанты обнаруживаются: точное сравнение имён и
правила — SBX08; ошибка `lstat` как «пути нет», пропуск неперечисляемого
каталога, непрочитанный каталог как пустой — SBX09; без проверки прав и без
прав в подписи — SBX10; не-каталог как пустой — SBX06; без класса
`scope-violation` для непрочитанного пути — SBX11 (gates) и T05 (runner).
Полный `npm run check`. Живые модели не вызывались.
