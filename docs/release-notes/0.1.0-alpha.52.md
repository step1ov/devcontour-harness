# devcontour-harness 0.1.0-alpha.52

Выпуск собирает четыре изменения: строку сводки попыток по поручению в
`status` и `explain` (и `status --human`) с правилом в skill `harness`,
пакет передачи без попыток, прерванных штатной остановкой, страницу
документации о медленных окружениях и устойчивость скриптов проверки
репозитория под нагрузкой. `stateVersion`, `policyVersion`,
`handoffVersion` и `reportVersion` прежние; новые поля необязательны,
записи хранилища не меняются.

## Изменения

- **Сводка попыток в `status` и `explain`.** У поручений `status` —
  необязательное поле `works[].attemptSummary`, у `explain` — `attempts[]`
  (не больше 100 строк, затем `attemptsTruncated`): попыток всего, отказы по
  корзинам отчёта, таймауты, прерывания штатной остановкой (не отказы),
  принятые, остаток попыток и восстановлений группы и готовая строка
  `line`. `neutral` — незасчитанные отказы и их предел; на пределе строка
  говорит «исчерпан предел незасчитанных отказов», а у завершённых и
  отменённых поручений строка показывает их итоговое состояние. Числа
  считает `attemptSummaryOf` из `devcontour-harness/report` — та же
  функция, что строки поручений отчёта.
- **`status --human`** печатает строку на поручение; `explain --human` —
  раздел «Попытки». Библиотека: `attemptSummaryOf`, `attemptSummaryLine`,
  `acceptingAttemptOf`, `interruptedByShutdown`, `attemptSummaryView`,
  `attemptSummaries`, `attemptsByWork`, `repairJobOf` (одно правило задания
  группы для `explain` и `status`), `statusText`, `explainText`;
  необязательное `StatusSource.workflows` даёт остаток восстановлений.
- **Правило skill `harness`.** На вопросы «сколько ещё» и «насколько
  готово» агент цитирует `line` сводки и `result.outcome`, не оценивает
  время и не превращает остаток попыток в срок; «исправлено», «проверка
  прошла» и «принято» — разные состояния, принятым считается только
  `result.outcome: accepted`.
- **Пакет передачи без прерываний остановкой.** `failures` в
  `harness handoff` (`handoffPack`) больше не содержит попыток, прерванных
  штатной остановкой controller (`interrupted: "shutdown"`): они исключаются
  до предела `HANDOFF_LIMITS.failures` (10) и не вытесняют настоящие провалы
  после перезапуска. Их число — новое необязательное поле `interruptions`,
  в Markdown — строка «Прервано штатной остановкой»; `truncated.failures`
  считает только настоящие провалы.
- **`docs/slow-environments.md`.** Новая страница: пределы времени фаз и
  gates с умолчаниями, условные gates (`when.paths`), режим графа, ресурсы,
  цена lifecycle и `prepare`, `integrationReuse`, слой `lean` и
  `harness gates --fail-fast` перед долгим циклом. Поля таблицы пределов и
  их умолчания сверяет тест со схемой политики. Поведение не меняется.
- **Скрипты проверки репозитория под нагрузкой.** `npm run check` и
  статические проверки не останавливаются, если `ps` недоступен или
  отвечает медленно: остановка сразу сигналит своим шагам, срок SIGKILL
  отсчитывается от первого сигнала каждого процесса, вывод о выживших —
  по снимку не раньше чем через 2 с после SIGKILL, процесс с pid 0 не
  сигналится. Без снимка в конце печатается «process leak check not
  performed (ps unavailable)». Пакет и его договоры не меняются.

## Совместимость

- Хост, который сравнивает ответ `status` побайтно с прежним, убирает поле
  `attemptSummary`. Строгие схемы прежних версий не принимают
  `attemptSummary` и `attempts`, а `status --human` прежняя версия
  отклоняет `INVALID_INPUT`.
- Хост, который сам отфильтровывал прерывания из `failures` пакета
  передачи, может убрать свой фильтр. Прежняя строгая схема пакета не
  принимает поле `interruptions`.
- Подробности — [upgrade](../upgrade.md).
