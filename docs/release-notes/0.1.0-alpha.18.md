# devcontour-harness 0.1.0-alpha.18

Проверка gates на закреплённом SHA исполняет их с теми предпосылками, на
которые опирается профиль. Включает всё из [0.1.0-alpha.17](0.1.0-alpha.17.md).
Формат состояния, gates попыток, правила находок, изоляция, принятие target
ref и `maxAttempts` не менялись.

## Что нового

- **Предпосылки проверки вне задачи.** `runGatesAt` брал только явные
  `dependsOn`. В профиле, который опирается на порядок массива (установка
  первой, без `dependsOn`), проверка одного test gate шла без установки и
  падала на отсутствующих модулях, хотя задачи проходили: их область называла
  установку явно. Теперь область проверки — названные gates и предпосылки
  каждого (`standaloneScope`), порядок — тот же `orderedScope`, что у попытки
  (прежний внутренний `ordered` runner, без изменения поведения).
  Предпосылки (`gatePrerequisites`): у gate с объявленным `dependsOn` —
  замыкание по `dependsOn`; у gate без поля `dependsOn` — все более ранние
  gates вида `check` со своими предпосылками. Более ранние test gates не
  добавляются. Каждый gate посещается один раз, поэтому `dependsOn` на более
  поздний gate вместе с неявным ребром не зацикливается. Область задачи
  по-прежнему исполняется как записана.
- **Явный `dependsOn: []` — без предпосылок.** Объявленный пустой
  `dependsOn` — режим графа: неявных предпосылок нет. Порядок массива
  действует только для gate без поля.
- **Все провалы сразу.** Провал gate больше не останавливает проверку:
  исполняются все названные gates, результат перечисляет каждый непрошедший
  (`failures`; `failure` — первый, как раньше). Пропускается только gate,
  чья явная предпосылка (`dependsOn`, `explicitPrerequisites`) не прошла, — он
  назван с этой причиной. Провал неявной предпосылки (раннего check gate) не
  скрывает исход тестов: исполняются и названы оба. Evidence по-прежнему
  пишется через запись хоста и привязано к SHA.

## Совместимость

Формат состояния не меняется. `GatesAtResult` получает поле `failures`;
хост, ждавший остановки на первом провале, получает теперь все исполненные
gates. Новые экспорты: `orderedScope`, `gatePrerequisites`,
`explicitPrerequisites`, `standaloneScope`. Матрица — [upgrade](../upgrade.md).

## Проверка выпуска

Затронутые тесты на реальных Git-фикстурах (`gates-at`: профиль в порядке
массива с установкой первой и без `dependsOn`, петля через неявное ребро,
пустой `dependsOn`, цепочки двух и трёх уровней, смешанная цепочка, провал
неявной предпосылки; `runner` T01, T09); каждый новый тест обнаруживает свой
мутант реализации. Полный `npm run check` перед публикацией выполняет
ведущий. Живые модели не вызывались.
