## Тонкий режим (`harnessMode: thin`)

Новый режим рядом с облегчённым и строгим ([thin-mode.md](../thin-mode.md),
`harness guide thin`). Окружение — как в облегчённом (исполнитель и gates на
хосте, граница записи); поток — тоньше. Исполнитель считается честным, но
ошибающимся; качество дают проверка на чистом checkout и одно независимое
ревью против постановки.

- **Одна сессия исполнителя на работу.** Первая сдача — новая сессия,
  следующие — продолжение (`codex exec resume`, `claude --resume`) с
  причиной отказа, хвостами проверок и ID находок. Исполнитель сам гоняет
  проверки своего поручения и сдаёт, когда они зелёные.
- **Сдача:** коммит дерева работы → слияние с текущей целью на чистом
  checkout → gates поручения → одно ревью → CAS цели. Слияния одного
  репозитория — по очереди.
- **До трёх сдач, затем ведущий.** Сбой среды — один автоповтор, затем
  ведущему без засчитывания (`gate-environment`); первый конфликт слияния —
  повтор без ведущего, повторный — `merge-conflict`. `retry --reset`
  сохраняет дерево и начинает новую сессию со сводкой; `retry --start-over`
  начинает работу заново.
- **В тонком режиме нет:** применимости по умолчанию, переноса результатов
  на интеграцию, правил «тот же дефект дважды», удержаний инфраструктуры и
  второго прохода ревью.
- Планирование — 3–5 работ на фичу (`THIN_PLAN_SIZE` вне диапазона).
- `harness init --harness-mode thin`; `doctor` называет режим и
  предупреждает, если CLI исполнителя не умеет продолжать сессию.

Облегчённый режим остаётся по умолчанию до итогов пилота; строгий заморожен.
