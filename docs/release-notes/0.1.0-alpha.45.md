# devcontour-harness 0.1.0-alpha.45

Gate задачи может быть условным: `when: { paths: [...] }`. Runner решает по
настоящему diff Git, а не по отчёту исполнителя, и за неприменимый gate
пишет evidence `not-applicable`, которое не считается ни PASS, ни провалом.
`stateVersion` и `policyVersion` прежние; политика без `when` даёт прежние
digest и поведение.

## Изменения

- **Условные gates.** `repositories[].gates[].when.paths` — 1–64 шаблона
  путей от корня репозитория (POSIX-glob `**`, `*`, `?`, `{a,b}` без
  вложенности; без `..`, `.`, ведущего `/`, `\`, `[]` и отрицания).
  Совпадение без учёта регистра и в NFC; шаблон задевает всё внутри
  совпавшего каталога и каталоги-предки своего буквального префикса
  (gitlink подмодуля). `policyIssues` требует у репозитория хотя бы один
  test gate без `when` и отклоняет `when` у генеративного gate
  (`property`); у `workspaceGates` поля нет.
- **Решение от последнего зелёного SHA.** Опора — integration SHA принятой
  попытки репозитория, где gate прошёл под тем же основанием `gateBasis`
  (определение gate и его ресурсы, транзитивные предпосылки, окружение,
  lifecycle, `prepare`, хранилище зависимостей, toolchain, изоляция, версия
  harness) и который — предок базы попытки. Diff кандидата —
  `зелёный..candidate`, интеграции — ещё и `зелёный..integration`, так что
  коммиты других задач и мимо harness входят в решение. Gate исполняется,
  если зелёного SHA нет; diff не прочитан, неполон, больше 5000 путей или
  пуст; задет шаблон `when.paths`; задет неявный вход (`protectedPaths`,
  `.harness/`, манифесты, lockfiles, файлы версий инструментов,
  `.gitattributes`, `.gitmodules`, `.lfsconfig` в любом каталоге, пути из
  argv команды gate); gate нужен доказательству поручения (`proofGates`) или
  он — предпосылка исполняемого gate. Общие настройки инструментов
  перечисляют в `when.paths` сами.
- **Evidence `not-applicable`.** Запись `passed: false`, `exitCode: -1`, без
  команды и лога, с полем `notApplicable` (`gateDigest`, `patterns`,
  `ranges`, `count`, первые 50 путей `files`, `pathsDigest`). Исполненный
  условный gate пишет в запись `test` поле `gateBasis`. Событие
  `attempt.gate` несёт `notApplicable: true`, ссылка evidence receipt — вид
  `not-applicable`, проекция попытки — `gates.notApplicable`. Приёмка и
  получатель receipt засчитывают неприменимость только обычному gate с тем
  же `gateDigest`, не нужному доказательству и не опоре исполненного gate;
  запись `test` того же gate и SHA решает раньше. Доказательства
  требований, testcase и свойств читают только записи `test`.
- **Покрытие набора на итоговом SHA.**
  `coverageChanges(repoPath, evidence, finalSha)` строит объединённый diff
  от зелёного SHA каждой записи неприменимости до итогового SHA;
  `uncoveredGates(repositories, works, changes, finalShas)` и
  `Engine.uncoveredGates(workIds, changes, finalShas)` считают пропущенный
  gate непокрытым, если diff его задевает, отсутствует, неполон, кончается
  не на `finalShas[repo]`, не начинается от зелёного SHA каждой записи или
  записан под другим определением gate. Хост исполняет такие gates один раз
  через `runGatesAt`. Совместная проверка не меняется.
- **Защита git хоста.** `gitHardening` несёт `--no-replace-objects` (и
  `GIT_NO_REPLACE_OBJECTS=1` для дочерних git): объекты замены не влияют на
  diff, требования, область записи и применимость; `refs/replace/*` или
  `info/grafts` делают diff неполным. Diff применимости идёт с
  `--no-renames`, `--no-ext-diff`, `--no-textconv`, `--no-relative` и
  `--ignore-submodules=none`, так что смена gitlink подмодуля видна.
- **Новые экспорты.** `changedPaths`, `coverageChanges`, `gateBasis`,
  `gateDecisions`, `gatePathRegExp`, `matchingPaths`, `notApplicableProblem`,
  `pathApplicability`, `proofGates`, типы `ChangedPaths`, `GateDecision`,
  `PathDecision`.

## Совместимость

- Прежний хост читает `attempt.gate` с `notApplicable: true` как провал, а
  прежний получатель receipt отклоняет вид ссылки `not-applicable`: хост
  понимает новый вид evidence до того, как в политике появится `when`.
- Хост со своим хранилищем сохраняет вид `not-applicable` и поля `gateBasis`
  и `notApplicable` и показывает неприменимый gate отдельно от PASS и
  провала. Хост, проверяющий профиль набора на итоговом SHA, передаёт
  `changes` из `coverageChanges`, `finalShas` и gates политики harness.
- Основание включает версию harness: после обновления каждый условный gate
  исполняется один раз. Добавление `when` меняет digest политики —
  согласования, привязанные к нему, повторяют.
- Состояние с evidence `not-applicable` или полями `gateBasis` и
  `notApplicable` прежние версии отклоняют: откат — через копию. Без
  условных gates откат возможен без изменений состояния.
