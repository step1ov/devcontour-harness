# devcontour-harness 0.1.0-alpha.35

Нехватка окна контекста claude — свой класс отказа `context-exhausted`
вместо `unknown`: короткая политика повторов, собственный код остановки и
понятная причина. `stateVersion` и `policyVersion` прежние.

## Изменения

- **Класс отказа.** `context-exhausted` распознаётся по `terminal_reason`
  результата claude. `prompt_too_long` на первом ходе (`num_turns` ≤ 1) —
  `contextLimit: prompt-too-long`, без повтора: поручение не помещается в
  окно, повтор того же входа бесполезен. `blocking_limit` или переполнение
  после ходов работы — `blocking-limit`, один повтор. Попытка засчитывается.
- **Остановка.** Код `CONTEXT_EXHAUSTED` (класс `refused`, exit code 3) в
  `stopReason`, `explain` и пакете передачи; в отчёте — корзина `incomplete`.
  Сообщение стабильное; подсказка о сокращении поручения — только у writer.
- **API.** `repairRepeats` и `lastContextLimit` экспортированы рядом с
  `repairPolicy`; порт runtime получил необязательное
  `RuntimeResponse.diagnostics.contextExhausted`.

## Обновление

Новые значения аддитивны, но документ состояния разбирается строго:
alpha.34 и ниже не читают состояние с отказом `context-exhausted`. Откат —
вместе с копией каталога состояния, снятой до обновления. Строгие внешние
валидаторы `RunResult`, отчёта, пакета передачи и диагноза остановки
обновляются вместе с harness. Подробнее — `docs/upgrade.md`.
