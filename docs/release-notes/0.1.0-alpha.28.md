# devcontour-harness 0.1.0-alpha.28

Файлы, которые gate оставляет в рабочем дереве, — скриншоты визуальной
проверки, отчёты, JSON наблюдений — теперь сохраняются как доказательства
вместе с логом gate. Обязательные gates, fencing и привязка доказательств к SHA
не меняются; исход gate от копирования не зависит.

## Изменения

- **`artifacts` у gate поручения.** Необязательный список из 1–16 путей
  репозитория (файлы или каталоги). После gate — пройден он или нет — обычные
  файлы `.png .json .txt .xml .log` копируются в `<каталог фазы>/<gate>.artifacts/`.
  Пределы: 64 файла, 8 МБ на файл, 20 МБ всего, 4096 просмотренных элементов
  каталога.
- **Запись в evidence.** Новое необязательное поле `artifactFiles`: каталог,
  `files[]` с путём, sha256 и размером копии, `skipped[]` с причиной (`missing`,
  `symlink`, `hardlink`, `outside`, `not-regular`, `extension`, `secret`,
  `file-limit`, `total-limit`, `count-limit`, `scan-limit`, `copy-failed`).
  Ничего не пропадает молча.
- **Граница доверия.** Символические ссылки не разыменовываются ни на каком
  уровне, жёсткие ссылки и пути вне дерева пропускаются. Секреты окружения в
  текстовых копиях маскируются побайтно; файл, в котором секрет остаётся
  (двоичный, UTF-16), не копируется. Имя файла с секретом — тоже пропуск.
  Каталог копий очищается перед прогоном с защитой от удаления дерева;
  отменённая проверка ничего не копирует и не удаляет.
- **Совместные проверки.** Gates workspace с объявленными `artifacts` теперь
  сохраняют и сами копии, а не только digest.
- **Остаточный риск.** Процесс, переживший gate, при `isolation: none` может
  подменить родительский каталог ссылкой между проверкой и открытием файла;
  harness останавливает дочерние процессы gate до копирования.

## Обновление

Пакет alpha.27 остаётся неизменным. Перед обновлением остановите writers и
сохраните копию состояния. Без `artifacts` политика и её digest не меняются.
Состояние с `artifactFiles` читает только alpha.28 и новее: откат — через копию
состояния. Подробнее — `docs/upgrade.md`.
