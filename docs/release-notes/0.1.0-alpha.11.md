# devcontour-harness 0.1.0-alpha.11

Разрешение профилей в форме хоста. Gates, `maxAttempts`, бюджеты попыток и
повторов, правила находок, изоляция и принятие target ref не менялись.

## Что нового

- **`resolveProfile(ref, { layerSchema })`** — хост, у которого закреплены
  профили своей формы (другие runtime ролей, свои поля ролей и инструкций,
  нестрогие вложенные объекты, свои правила окружения и ID шагов), передаёт
  схему Zod своего файла. Она разбирает каждый слой вместо `StackProfile`;
  gates, шаги, роли и `contextPacks` в результате остаются в её форме
  (`ResolvedProfileOf<L>`). Безопасность файлов, обход `extends`, сложение
  слоёв, проверки gates (порядок, зарезервированный gate, JUnit), digest и
  `includeLeafContent` — прежние.

## Изменения договора

Только добавления:

- опция `layerSchema` (`ResolveProfileLayerOptions<L>`), типы `ProfileLayer`
  и `ResolvedProfileOf<L>` в корне пакета.

Отказы: `layerSchema` не схема Zod (в том числе `null`) — `INVALID_INPUT`,
путь `['options','layerSchema']`; слой, который схема хоста разобрала без
полей сложения (`ProfileLayer`), — `INVALID_INPUT`
«layerSchema: слой … не даёт форму профиля». Без опции результат
`resolveProfile` тот же, что в alpha.10.

## Совместимость

Формат состояния не менялся: alpha.11 читает всё, что читает alpha.10
([upgrade](../upgrade.md)).

## Проверка выпуска

`npm run check` (lint, typecheck, schemas, build, весь набор тестов, package
smoke из установленного архива) на macOS arm64, Node.js 24; package consumer
fixture разрешает профиль в форме хоста (runtime `demo`, `reviewVendor`,
`revision` инструкций) из установленного архива. Ответы моделей в
fixture-маршрутах запрограммированы: это механика, не качество живого агента.
