# devcontour-harness 0.1.0-alpha.62

`stateVersion`, `policyVersion`, `handoffVersion`, `reportVersion` и
`viewVersion` прежние; `viewRevision` — 4. Схема представления оператора
расширена совместимо (необязательные `progress.queue.neverRun` и
`scopeReason`); схема состояния не меняется. Порядок обновления и отката —
`docs/upgrade.md`, раздел alpha.62.

## Изменения

### Представление оператора

- Каталог, с которым harness ещё ничего не запускал (нет состояния или нет
  ни работ, ни попыток, ни записей вызовов, ни controller), больше не
  выглядит как идущая очередь: `progress.queue.neverRun: true` и строка
  «Ещё ничего не запускали — ведущий начнёт с harness run.».
- Без снимка задач трекера `scope` нет, а `scopeReason: 'no-snapshot'`
  говорит почему: панель отличает «harness ещё не читал задачи» от версии
  harness, которая срез не сообщает. База коннектора, которую эта версия не
  прочитала, — `scopeReason: 'unreadable'`, а не «снимка нет».

### Обновления

- `status --human` и представление оператора сравнивают проверенное
  обновление с версией harness, установленной в каталоге установки проекта, —
  по тому же правилу, что `update --check` (`installPrefix`). Раньше они
  сравнивали его с версией запущенного процесса: при глобальной установке или
  запуске из исходников доступное обновление показывалось как «обновлений нет».
- Тесты `update-cli` больше не зависят от номера версии пакета.
