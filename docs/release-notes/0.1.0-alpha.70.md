# devcontour-harness 0.1.0-alpha.70 (черновик)

`stateVersion`, `policyVersion`, `handoffVersion`, `reportVersion` и
`viewVersion` прежние; `viewRevision` — `10`. Всё новое в политике,
состоянии, ответах CLI и представлении — необязательные поля. Порядок
обновления и отката — `docs/upgrade.md`, раздел alpha.70.

Кто принимает решения — прежнее ([принцип](../principles.md#кто-принимает-решения)).
Новые решения выпуска — технические, у ведущего: режим второго прохода
ревью, принятие или отклонение предложений исполнителя (задачи-продолжения
и разделения). Уровень безопасности облегчённого режима выбирает владелец;
harness его только определяет.

## Изменения

### Двухпроходное ревью ([review-protocol.md](../review-protocol.md), §11)

- **Подозрение → опровержение.** Когда первый проход отклоняет результат,
  второй — свежий вызов reviewer — пытается опровергнуть каждую
  блокирующую находку. Подтверждённые остаются, опровергнутые снимаются с
  основанием (`EvidenceRecord.reviewPasses`). Ложный отказ больше не
  тратит попытку.
- **`review.passes: off | on-reject | always`** (или по видам: `code`,
  `release`, `sensitive`, `sensitiveLabels`). Умолчания: `on-reject` для
  ревью попыток, `always` для приёмки выпуска и работ с метками
  security/payments/auth; `always` ищет и пропущенные первым находки.
  Настраивает ведущий; поле не входит в digest исполнения.
- Отказ второго вызова — действует первый проход, находки остаются.

### Задачи-продолжения и разбор в начале попытки

- Исполнитель сдаёт сделанное с доказательствами и предлагает
  задачи-продолжения на остаток вне критериев (`followUpTasks`). Reviewer
  видит предложения и отклоняет критерий, перенесённый в продолжение.
- Разбор в начале попытки: «делаю / разделить / спросить» (`triage`).
  Разделение — к ведущему: попытка не засчитана (`needs-lead`, причина
  `writer-split`), кода нет.
- Решает только ведущий (или оператор): `harness proposal --work W
--proposal P --decision accept|reject --reason R`. Принятие граф не
  меняет — принятое вносится в план обычным ревью плана. Отклонённое
  разделение следующая попытка получает с основанием ведущего.

### Общее исследование задачи

- Исполнитель возвращает исследование (`research`); оно сохраняется у
  работы и открывает запрос следующих попыток и зависящих работ сразу
  после постановки — общий префикс для кеша подсказки.
- Договор ответвления сессии (`session.kind: fork`,
  `RuntimeCapabilities.sessionFork`) для адаптеров, которые это умеют;
  reviewer всегда начинает заново и исследования не видит. Встроенный
  адаптер CLI ответвление пока не объявляет.

### Выпуск

- **Шаг документации**: работа с меткой `docs`, зависящая от всех
  корневых работ, принимается до приёмки выпуска. `release.docs:
required | advisory | off` (умолчание `advisory`).
- **Ведущий не добавляет требований без источника**: у каждого
  критерия, который пишет ведущий, — источник (`criteriaSources`:
  постановка, ответ владельца, находка ревью, контекст); ревью плана
  помечает критерий без источника (`unsourced-criterion`).

### Облегчённый режим

- **Отказ до вызова исполнителя — отказ окружения** (исправление пилота):
  подготовка окружения (lifecycle, docker/compose, установка), упавшая
  до вызова writer и до кандидата, больше не «неизвестна» и не
  засчитывается в попытки: класс `environment`, причина `preflight`,
  выдача держится как остановка окружения.

- **Git под границей записи — граница alpha.69, совет вместо доступа**
  (исправление пилота): каталог git дерева попытки и весь `.git` закрыты
  на запись; работают команды для чтения (`git status`, `git diff`,
  `git diff --exit-code`, `git log`, `git show`), а `git add`,
  `git commit`, `git stash`, `git checkout -- .`, `git reset` отказывают
  (`git stash` — молча, кодом 1). Gate, провал которого объясняет только
  отказ git в `.git`, получает совет `GATE_GIT_WRITE` (gate не меняет
  состояние git) и засчитан исполнителю; если тот же gate так же падает
  на базе (структурная отметка итога `harness gates --sha`), это
  определение gate — удержание для ведущего. Провал с упавшими тестами,
  утверждением или сигналом засчитан как обычно, совет — дополнением.
- **Запись кандидата controller** — не через HEAD: сверка метаданных git
  дерева, которые создал controller (расхождение, ссылка вместо файла —
  нарушение области), index заново от базы, `write-tree`,
  `commit-tree -p <база>`, `update-ref` ветки попытки с ожидаемым прежним
  значением; без запомненных метаданных кандидат не пишется. После записи
  index дерева совпадает с HEAD.
- **stash владельца закрыт под границей и на чтение**: `git stash pop` и
  `apply` не накладывают его на дерево попытки.
- **Уровни безопасности** ([light-mode.md](../light-mode.md#уровни-безопасности)):
  граница записи → отдельный пользователь ОС → контейнер → VM. `doctor`
  второй заметкой показывает текущий уровень (`mode.securityTier`);
  выбирает владелец.
- **Сервисы попытки**: `harness env-up` / `env-down` / `env-sweep` —
  compose под именем проекта попытки с `--wait`, динамические порты в
  файле окружения попытки (`HX_<СЕРВИС>_<ПОРТ>`, gates получают их в
  окружении), при отказе готовности — `compose ps -a` и хвосты журналов
  нездоровых сервисов, уборка проектов не идущих попыток.

### Оператору

- **Справочник причин отказов** ([failure-causes.md](../failure-causes.md)):
  что значит каждый класс отказа и каждая причина окружения, кто
  действует, что обычно помогает. `explain` и `status` (последний отказ)
  ссылаются на него.

### Ревью alpha.70, раунд 1

- Второй проход снимает явный отказ первого, только если опроверг все его
  блокирующие находки; идёт в своём detached-дереве и вердикт первого
  прохода в отказ не превращает.
- (История; заменено в раунде 4 границей alpha.69.) Git под границей
  записи пробовали открыть через каталог git дерева попытки с отдельным
  хранилищем объектов.
- Отказ до кода исполнителя — только при подготовке окружения на базе;
  взятый или восстановленный код исполнителя засчитывается.
- Порты сервисов — по фазам: после setup, до setup снимаются.
- `env-sweep` — только стеки `env-up` этого состояния у не идущих
  попыток, живость перед снятием, без `--yes` — список.
- `release.docs: required` держит и `release done`; шаг документации —
  в границах текущего выпуска.
- Расход ужимается при пределе представления и упорядочен по времени;
  предложения и исследование переживают редакции графа; ссылка
  справочника — на master; повторное разделение после отклонения
  засчитывается.

### Ревью alpha.70, раунд 2

- (История; заменено в раунде 4.) Каталог git дерева попытки оставляли
  открытым без хранилища объектов.
- Запись кандидата не через HEAD (`write-tree`, `commit-tree`,
  `update-ref` с ожидаемым значением) и сверка метаданных git дерева —
  остаются.
- `env-sweep`: записи владения — только из каталога артефактов известных
  попыток, проект — выведенный из попытки и репозитория; своя запись у
  каждого репозитория.
- Порты: снимаются только записанные `env-up`; переменные политики с
  префиксом `HX_` остаются. Маска журналов — по объявленным секретам
  (имена передаёт controller), до обрезки, и ещё раз после setup и ready.
- Второй проход приёмки выпуска, изменивший своё дерево, не принимается;
  запрос второго прохода говорит, что его дерево не подготовлено.
- Попытки в расходе — по времени; отклонённое разделение — только для
  той же постановки.

### Ревью alpha.70, раунд 3

- (История; заменено в раунде 4.) Отдельный index controller
  (`GIT_INDEX_FILE`) и правила для `config.worktree` под границей.
- Остаются: `config.worktree` и ссылки вместо файлов каталога git дерева
  сверяются перед записью кандидата (нарушение области); без запомненных
  метаданных кандидат не пишется; stash владельца под границей закрыт и
  на чтение.
- Дерево второго прохода приёмки выпуска убирается на любом исходе, и при
  отмене; проверка дерева — одно правило в обоих путях (без игнорируемых
  файлов).
- Отклонённое разделение без записанного основания (`orderDigest`) больше
  не держит.
- В light-mode.md — раздел «Чего граница записи не защищает».

### Ревью alpha.70, раунд 4

Каждый раунд ревью с тех пор, как каталог git дерева попытки открыли на
запись (чтобы gate мог взять блокировку index), находил новый класс
проблем: хранилище объектов и его перенос, переключение ветки владельца,
ссылки и флаги index, `config.worktree`, отдельный index controller с его
регистрацией, устаревший index дерева и утечки файлов. Причина одна —
открытый каталог git, поэтому git под границей возвращён к границе
alpha.69: каталог git дерева и весь `.git` закрыты на запись, работают
только команды для чтения, а исходный случай пилота — gate, который
убирал за собой через `git checkout -- .`, — решён советом, а не
доступом: такой провал называется `GATE_GIT_WRITE` с подсказкой, как
проверять без изменения git, и при том же провале на базе становится
определением gate (удержание для ведущего). Из прежних раундов остаются
независимые от этого проверки controller: сверка метаданных дерева перед
записью кандидата, запись не через HEAD (`commit-tree` и `update-ref` с
ожидаемым значением), отказ без запомненных метаданных, закрытый на
чтение stash владельца, уборка дерева второго прохода и основание
отклонённого разделения. Регистр index controller, `GIT_INDEX_FILE` и
правила для `config.worktree` убраны.

### Ревью alpha.70, раунд 5

- `GATE_GIT_WRITE` — только когда отказ git в `.git` единственное
  объяснение провала; отметка — структурная (`failureSummary.gitWrite`),
  итог на базе сверяется по ней, не по тексту. Признак отказа — отказ в
  правах на путь `.git` (занятый `index.lock` и общий отказ временного
  файла не считаются). Совет называет и `git stash`, который под границей
  отказывает молча.
- Тест: после записи кандидата и после интеграции gate видит чистый
  `git status` и `git diff --exit-code`.
- Общий провал обёртки в отчёте («Gate execution failed») — не
  самостоятельная причина: при одном только отказе git провал остаётся
  `GATE_GIT_WRITE` (и удерживается при том же провале на базе).

## Совместимость

- Отклоняющее ревью попытки стоит на один вызов reviewer больше; приёмка
  выпуска и работы с метками security/payments/auth — на один вызов на
  каждый раунд. Прежнее — `review.passes: off`.
- Wire-схема ответа writer требует `followUpTasks`, `triage`,
  `research` (допустимы `[]` и `null`); прежние ответы читаются.
- Gates, которые меняют состояние git (`git checkout -- .`, `git stash`,
  `git add`) под границей записи, как и в alpha.69, отказывают; теперь
  провал называется `GATE_GIT_WRITE` с советом.
- Откат на alpha.69 — копией состояния до обновления.
