# devcontour-harness 0.1.0-alpha.63

`stateVersion`, `policyVersion`, `handoffVersion`, `reportVersion` и
`viewVersion` прежние. Схемы ответов `smoke` и `doctor` расширены совместимо
(статус команды пробы `outside`, необязательные `writers[].loopback`,
`loopbackCommand`, `loopbackApplied`, `doctor.notes`); схема политики и
состояния не меняется. Порядок обновления и отката — `docs/upgrade.md`,
раздел alpha.63.

## Изменения

### Проба исполнителя: сеть loopback без развилки

- Шаг `writerProbe`, закрытый только локальным портом (`listen-denied` или
  EPERM без пути, как у Turbopack), у исполнителя, чья сеть закрыта и для
  локальных портов (codex без поля `network` или с `none`, claude с `none`),
  проба сама повторяет под `network: loopback` в той же изоляции: у codex
  сначала поддержка `network_proxy` и проверка границы
  `harness-loopback-check`. Повтор идёт в свежем рабочем дереве и со свежим
  TMPDIR, подготовленными как для первого прохода, а не на остатках закрытого
  прохода: кеш Turbopack (`next build`) повторял его отказ, и шаблон получал
  ложный `not-enough`. EPERM без пути рядом со строкой «binding to a port» —
  `listen-denied`. Итог — `writers[].loopback` (`resolves`,
  `not-enough`, `unavailable`) с причиной простыми словами и
  `decision: "lead"`.
- При `resolves` проба печатает одну команду (`loopbackCommand`):
  `harness smoke … --writer-probe --apply-loopback` записывает
  `"network": "loopback"` в профиль инструментов исполнителя (нет профиля —
  новый `writer-loopback` у его ролей), кладёт запись с причиной в
  `writerProbe.loopbackApplied` и `loopback-receipt.json` и повторяет пробу
  под новой политикой (тоже в свежем дереве); `--human` печатает исход каждого
  шага повтора. Интернет, домены, области записи, `isolation.mode` и
  сеть ревьюера не меняются. Запись идёт под замком `<политика>.lock` и
  только поверх тех байтов, которые проверила проба: файл, изменённый после её
  чтения, чужой живой замок или чужая запись сразу после замены — отказ
  `PATH_CONFLICT`. Сеть профиля входит в `isolationDigest`: согласованные
  графы согласуются заново.

### Проверки в браузере — вне исполнителя

- Шаг, в выводе которого браузер не запустился под песочницей исполнителя
  (агент-браузер, Puppeteer, Playwright, Chrome или Chromium, в том числе с
  `Abort trap`), — статус `outside`, а не `blocked`: это ожидаемо, проба
  остаётся зелёной (exit 0), если остальное доступно, и печатает одну строку
  простыми словами. Имя шага и аргументы этого не доказывают: отказ записи или
  сети у `browser-bundle` или `pnpm add -D @playwright/test` остаётся
  `blocked`. `doctor` с политикой называет в `notes` (`browser-checks …`), не в
  `problems`, шаги с инструментом запуска браузера в argv (`agent-browser`,
  `playwright test`, `cypress run`, `verify:browser`); шаг только со справкой
  или версией (`--help`, `-h`, `--version`, `-V`) — не проверка.
- `harness-setup` и `harness` больше не превращают оба случая в вопрос
  владельцу: loopback применяет ведущий, проверку в браузере делают gate
  harness, только если она проходит на HEAD под harness.

### Обновления

- `harness update --check`: реестр не знает пакет (E404) — «пакет … ещё не
  опубликован в npm»; пакет есть, версии нет (`npm pack` — ETARGET, `npm view`
  — E404 «No match found for version») — «версия … пакета … ещё не
  опубликована в npm» вместо «code E404». Прочие отказы npm — прежняя
  строка. Установленная версия новее тега канала (сборка до публикации) —
  «Обновление не нужно: установлен harness X — новее опубликованного в npm Y:
  эта версия ещё не опубликована» вместо «Обновлений нет».
