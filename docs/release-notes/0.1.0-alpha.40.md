# devcontour-harness 0.1.0-alpha.40

Проверки reviewer при ревью интеграции согласованы с базой, которую видит
reviewer. `stateVersion` и `policyVersion` прежние.

## Изменения

- **База проверок reviewer при ревью интеграции.** С 0.1.0-alpha.39 diff
  ревью интеграции считается от target, на который сделано слияние (первый
  родитель integration SHA), но инструмент проверок reviewer
  (`trustedBase` спецификации probe) по-прежнему сравнивал входы установки
  зависимостей с базой попытки. Теперь `trustedBase` — база самого ревью:
  у интеграции — target слияния (тот же коммит, что `Base commit` запроса),
  у кандидата — база попытки, как раньше. Когда target сдвинулся после
  начала попытки, отказ установки в проверке reviewer распознаётся как
  `dependency-network` относительно того target, на котором проверяется
  слияние.
- Без изменений: `shas.base` результата, записи попытки и проверка
  «изменений нет» (кандидат совпадает с базой попытки) по-прежнему
  используют базу попытки. Gates и шаги `prepare` интеграции тоже
  по-прежнему передают базу попытки как `trustedBase`: если target
  сдвинулся и lock-файл слияния отличается от базы попытки, отказ реестра
  там классифицируется как `gate`, а не `dependency-network`.

## Обновление

Формат состояния и политики прежний. Подробнее — `docs/upgrade.md`.
