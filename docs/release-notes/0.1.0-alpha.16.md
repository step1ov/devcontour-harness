# devcontour-harness 0.1.0-alpha.16

Проверка файлов эталонных наборов без ложных отказов. Включает всё из
[0.1.0-alpha.15](0.1.0-alpha.15.md) и [0.1.0-alpha.14](0.1.0-alpha.14.md):
обе — локальные выпуски, в npm не публиковались; первая публикуемая версия с
эталонными наборами — alpha.16. Gates, `maxAttempts`, бюджеты попыток и
повторов, правила находок, изоляция, принятие target ref и формат состояния
не менялись.

## Что нового

- **Отказ по файлу набора — только по строковому литералу.** В alpha.15
  кандидат отклонялся, если изменённый файл где угодно содержал путь или имя
  файла набора: комментарий, свой тест исполнителя, `data.json` при наборе
  `a.json`. Теперь имя файла набора должно стоять целым токеном внутри
  строкового литерала (`'…'`, `"…"`, `` `…` ``); комментарии `//` и `/* */` и
  файлы без кода (`.md`, `.txt`, `.rst`, `.adoc`, `docs/`) не проверяются.
  Тесты исполнителя проверяются тем же правилом. Ложный отказ тратил попытку.
- **Reviewer контракта видит минимумы.** `referenceNote` показывает общий
  минимум обязательства, минимумы семейств и доли семейств каждого набора.
  Сравнения долей с фактическим размером файлов набора нет — это описано в
  [договоре](../contracts.md#способы-исполнения-обязательства-property-и-reference).
- Новый экспорт `setFileReference(path, text, sets)`.

## Совместимость

Формат состояния и договор те же, что в alpha.15. Обновление и откат — по
[upgrade](../upgrade.md).

## Проверка выпуска

`npm run check` на macOS arm64, Node.js 24.3. `tests/reference.test.ts`
(15 тестов): комментарий, текст, свой тест без литерала, похожие имена и
непарная кавычка — без отказа; литеральный путь, `'golden-a.json'`, путь в
шаблоне, `../имя` и импорт из теста исполнителя — отказ. 36 из 36 мутантов
реализации обнаружены. Живые модели не вызывались.
