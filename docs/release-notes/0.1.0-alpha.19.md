# devcontour-harness 0.1.0-alpha.19

Меньше трения в цикле исполнения и жёстче граница песочницы: провал
интеграции, вызванный средой, повторяется один раз, установка зависимостей
не падает на каталогах IDE внутри `node_modules`, а git хоста не исполняет
конфигурацию, которую записал чужой код. Включает всё из
[0.1.0-alpha.18](0.1.0-alpha.18.md). `maxAttempts`, правила находок и
принятие target ref не менялись.

## Что нового

### Цикл исполнения

- **Ограниченный повтор провала интеграции.** Собственный gate поручения,
  прошедший на кандидате и упавший на integration, повторяется один раз на
  кандидата на том же integration SHA, прежде чем засчитать отказ `gate`.
  Обе записи остаются; у повтора `recheck: {of, outcome}` — ссылка на первую
  запись и исход `flaky` (повтор прошёл) или `confirmed` (провал
  засчитывается как прежде). Лог повтора — в `integration/recheck/`, замер —
  стадия `integration-recheck:<gate>`. Удачный повтор принимает кандидата без
  новой реализации. Кандидат, переиспользованный следующей попыткой, второго
  повтора не получает; движок отклоняет второй повтор в попытке и исход,
  не согласованный с записью.
- **Контрпример не повторяется.** Провал, в отчёте которого названо
  проваленное свойство или случай корпуса, не повторяется: удачный второй
  запуск недетерминированной проверки не отменяет найденного входа.
- **Шире области gates.** Область gates задачи, поручения, потребителя и
  основания ревью вмещает до `GATE_SCOPE_LIMIT` (100, предел gates профиля)
  вместо 20; превышение — понятный отказ с величиной и исправлением.
  Константа экспортируется.
- **Дешевле такты.** `expire()` без истёкших попыток не открывает транзакцию
  записи; такт очереди читает активные попытки через необязательный быстрый
  путь `ExecutionView.activeAttempts`. Завершённое задание workflow сообщает
  израсходованные попытки стадий, а не сброшенный счётчик.

### Песочница

- **Каталоги IDE внутри `node_modules` открыты.** Пакеты публикуют `.idea/`,
  и установка в чистом дереве падала с EPERM при любом коде. На macOS srt
  запускается из служебного каталога проверки, а обязательные запреты
  задаются явно на весь checkout: конфигурация shell, git, MCP и Claude,
  `.git/hooks`, `.git/config` — на любой глубине; `.idea`/`.vscode` — в
  корне и в каждом существующем подкаталоге до глубины 3, кроме
  `node_modules`. Linux не меняется (srt пропускает `node_modules` сам).
- **Явные запреты `.git`.** На macOS закрыты файл `.git` рабочего дерева,
  перенаправления обычного `.git` (`commondir`, `gitdir`, `config.worktree`)
  и вложенные `.git` на любой глубине; на Linux — существующий файл `.git`.
  Дерево больше предела перечисления — отказ класса `environment`, а не
  молча урезанные запреты.
- **Git хоста над деревом проверки (`git-trust`).** Каждый вызов git хоста
  сначала сверяет, куда git придёт: файл `.git` дерева, созданного
  `worktree add`, не изменён; gitdir и общий каталог лежат вне дерева и
  согласованы. Перенаправленный `gitdir`/`commondir` в обычном `.git` и
  вложенный репозиторий внутри известного дерева — отказ
  (`UntrustedCheckoutError`, в gate — `scope-violation`). Поверх —
  `-c core.fsmonitor=false -c core.hooksPath=/dev/null -c protocol.ext.allow=never`:
  hooks репозитория при коммитах harness не исполняются. Экспорт для хоста:
  `hostGitArgs`, `assertTrustedCheckout`, `UntrustedCheckoutError`,
  `gitHardening`, `rememberWorktree`, `forgetWorktree`, `worktreeKey`,
  `worktreeAddPath`, `resetGitTrust` (для тестов).
- **Сверка защищённых путей после gate.** Запреты песочницы видят только
  путь операции, и каталог, собранный в `node_modules` и перенесённый в
  дерево проекта, ими не закрыт. Вокруг каждого gate и работы исполнителя
  сравнивается снимок защищённых имён вне `node_modules`; новое или
  изменённое — `scope-violation` с путями в сообщении.
- **Класс `environment` — только по журналу ядра.** Отказ песочницы
  классифицируется как сбой среды, только когда журнал ядра macOS подтвердил
  отказ обязательного запрета внутри дерева проверки (команда проверки
  помечена уникальным токеном). Текст вывода (EPERM) свидетельством не
  служит; запись вне дерева и любой отказ на Linux остаются `gate`.

## Известные пробелы

- Регрессионные тесты в настоящей песочнице для запретов `.git`, для сверки
  защищённых путей после переноса каталога и для отказа по пределу
  перечисления не написаны (решение владельца проекта). Эти пути покрыты
  тестами SBX01–SBX05 и модульными тестами `git-trust`.
- Запреты на Linux и запуск/остановка наблюдения за журналом ядра тестами не
  покрыты.
- Поэтому два мутанта этих путей (D1, D2) выживают.

## Совместимость

Формат состояния: новое необязательное поле `recheck` у evidence gate и в
событии `attempt.gate`, области gates длиннее 20. Прежние версии
отклоняют такое состояние строгой схемой → откат через копию. Хост, у
которого хуки gate или writer меняют защищённые имена, получит
`scope-violation`. Матрица — [upgrade](../upgrade.md).

## Проверка выпуска

Затронутые тесты (`runner`, `engine`, `repair`, `planning-schema`,
`cli-h3-contract`, `probe-gates`, `review-inspection-runner`, `git-trust`,
`sandbox-install`, `boundaries`), lint, typecheck и `schemas:check`. Полный
`npm run check` перед публикацией выполняет ведущий. Живые модели не
вызывались.
