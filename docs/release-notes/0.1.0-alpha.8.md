# devcontour-harness 0.1.0-alpha.8

Самостоятельный маршрут для ведущего агента пользователя: подготовка проекта,
объяснение остановок и общие операции для хостов. Gates, `maxAttempts`, бюджеты
попыток и повторов, правила находок, изоляция и принятие target ref не
менялись.

## Что нового

- **`harness init`** — подготовка существующего Git-репозитория npm/pnpm без
  ручного JSON: профиль по lockfile (или `--profile`), политика из профиля и
  toolchain inspection, reviewer другого вендора. Запись только create-only в
  `.harness/`: `.gitignore`, `README.md`, `project.json` (решения: профиль,
  writer, путь state), затем `policy.json`. Чужие файлы не меняются; через
  symlink и вне корня ничего не пишется; конфликт — `PATH_CONFLICT` с путём.
  Повтор с теми же решениями ничего не пишет, прерванная подготовка
  продолжается по записанным решениям. Каталог state — вне репозитория.
  Репозиторий DevContour — `CONTROLLER_BUSY`. `--plan` — только план.
- **`harness explain`** — объяснение остановок: код, причина, фаза, кто
  действует (`controller`, `lead`, `user`), допустимый шаг и evidence. Прогноз
  повтора строится тем же порядком решений, что у движка. Только чтение: без
  повторов, вызовов моделей и изменений состояния, бюджетов, очереди и refs.
- **`--human`** у `init` и `explain` — явный текст вместо JSON; отказ остаётся
  JSON-конвертом, exit code тот же.
- **Сетевые отказы**: `EPROTO`, `ECONNREFUSED`, `ENOTFOUND`, `EAI_AGAIN`,
  `ETIMEDOUT`, `EHOSTUNREACH`, `ENETUNREACH` (как отдельные коды) и
  `TLS handshake failed/timeout` — класс `environment`: один автоматический
  повтор одного отпечатка в пределах бюджетов, `stopReason.code:
RUNTIME_UNAVAILABLE`. Явный класс, коды `HarnessError` и отказ провайдера
  (`provider-auth`) по-прежнему сильнее текста. Сохранённые прежние записи
  не переклассифицируются.
- **Общие операции для хостов**: подготовка файлов (`inspectPath`,
  `checkDestination`, `listRegularFiles`, `planFileWrites`, `applyFileWrites`)
  и проекции диагностики (`chainRoots`, `workProgress`, `nextAction`,
  `queueStop`, `explainStop`, `stopCodeOf`, `clipText`, `clipDeep`).
- **Бюджетное удержание в `status`**: `BUDGET_EXHAUSTED` в `blockers` готового
  поручения — по текущему расчёту бюджета (тому же, что у `claim`): после
  повышения лимита устаревшая причина не показывается, превышенный расход
  виден до следующего `claim`.
- Поставляемый skill описывает маршрут агента от установки точного архива до
  проверки результата ([standalone](../standalone.md)).

## Изменения договора

Только добавления:

- CLI-команды `init` (`writes: true`) и `explain` (`writes: false`), их схемы
  `data` в `cliDataSchemas`;
- коды ошибок `PATH_CONFLICT` (refused, exit 3) и `RESPONSE_TOO_LARGE`
  (input, exit 2). В `RunResult.stopReason` они не выдаются; перечень кодов в
  `run-result` и `result-envelope` расширен только допустимыми значениями;
- публичные схемы `project-manifest`, `stop-diagnosis`;
- subpath `devcontour-harness/projections` (без `node:*`, доступен браузеру);
  корень экспортирует те же функции;
- `repairPolicy` вынесен в модуль без `node:*` и реэкспортируется прежним
  путём; таблица не изменилась.

Прежние команды сохраняют конверт и exit codes; новые флаги (`--plan`,
`--writer`, `--human`) другие команды отклоняют `INVALID_INPUT`.

## Совместимость

Формат состояния не менялся: alpha.8 читает всё, что читает alpha.7
([upgrade](../upgrade.md)). Потребителю, разбирающему коды ошибок как
закрытое перечисление, нужно принять `PATH_CONFLICT` и `RESPONSE_TOO_LARGE`.

## Проверка выпуска

`npm run check` (lint, typecheck, schemas, build, весь набор тестов, package
smoke с маршрутом `init → validate → run → accepted` из установленного архива)
на macOS arm64, Node.js 24.3.0; отдельный package consumer fixture проверяет
общие операции из установленного архива. Ответы моделей в fixture-маршрутах
запрограммированы: это механика, не качество живого агента.
