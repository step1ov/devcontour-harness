# devcontour-harness 0.1.0-alpha.67 (черновик)

> Черновик заметок выпуска: номер пакета ещё 0.1.0-alpha.66; раздел
> `docs/upgrade.md` и матрица форматов — при выпуске.

`stateVersion`, `policyVersion`, `handoffVersion`, `reportVersion` и
`viewVersion` прежние; `viewRevision` — `7`. Политика получила необязательное
поле `repositories[].infra`, поручение — `kind` и `gateChanges`, draft
самостоятельного проекта — те же два поля; журнал — событие
`environment.reconciled`. Ответы `status`, `explain` и `cleanup` расширены
совместимо. Политики, графы и поручения без новых полей сохраняют digest.

## Изменения

### Работы инфраструктуры и бюджет настройки

- Новый вид работы `kind: infra` ([работы инфраструктуры](../infra-works.md)):
  мосты окружения, обёртки gates, приёмочные тесты в `.harness/` пишет
  исполнитель обычным циклом — попытки, gates, ревью кода, прогноз, путь
  работы, — а не ведущий во время настройки.
- `repositories[].infra.paths` — область инфраструктуры: только работы
  инфраструктуры её меняют, продуктовые — нет (защищённый путь). Политика
  отклоняет область, которая покрывает корни доверия (политика, профиль,
  связка, manifest, обновления, пакет контекста, установленный пакет) или
  файлы шагов на хосте (`lifecycle`, `prepare`, `dependencyBuild`,
  `preflight`, генераторы). Область входит в `isolationDigest`.
- Доверенная база gates: существующий файл gate работа инфраструктуры
  меняет, только если поручение называет его в `gateChanges` (входит в
  digest графа — изменение определения gate согласует ревью плана); иначе —
  `scope-violation`. Определение gate остаётся в политике. Продуктовые
  работы графа обязаны зависеть от работ инфраструктуры своего репозитория
  (`plan-check`/`validate`) и исполняют определение из принятой ревизии.
- Writer, reviewer кода и reviewer плана получают строку о виде работы и
  согласованных изменениях gates.
- Skill `harness-setup`: настройка — только конфигурация; новый код и
  унаследованные долги настройки — работы инфраструктуры первого плана;
  мягкий бюджет настройки 30 минут.
- Ход настройки: пока работ нет, `harness view` (`stage.progress`, обзор и
  документ настройки) и `harness status` (`setupProgress`, строка в
  `--human`) показывают шаги профиль, init, doctor, smoke, проба
  исполнителя, gates на HEAD, связка — с состоянием, временем и
  длительностью — и время настройки против бюджета. `doctor --policy`
  предупреждает `SETUP_OVER_BUDGET`, пока `run` не начинался, а настройка
  идёт дольше бюджета. `harness smoke` пишет итог рядом с логами
  (`<state>/gates-at/LS-*/result.json`).
- Представление: `works[].kind: 'infra'` у работы инфраструктуры.

### Очистка записей smoke

- `harness cleanup --run LS-…` принимает ID запуска smoke: повторяет
  teardown окружения, пока рабочее дерево на месте; если дерева нет, а
  ресурсов Docker с меткой прогона `devcontour.harness.run` нет (или
  lifecycle Docker не использует), запись `cleanup-failed` сверяется в
  `cleaned` с событием `environment.reconciled` (`reconciled[]` в ответе).
  Ресурсы остались или Docker не ответил — `NOT_READY` с тем, что осталось;
  запись не меняется. Команда ничего не удаляет.

### Вопрос держит только свою работу

- `status`: когда никто не запущен, у строки очереди `runner.ready` —
  сколько работ сдвинет новый запуск, `runner.heldByQuestion` — работы,
  которые держит только вопрос исполнителя, и строка «Очередь стоит — никто
  не запущен: запустите harness run: готово N задач, вопрос блокирует только
  X (ведущий).»
- `explain`: `queue {actor: lead, action: start-run, ready, heldByQuestion?,
line}`; в `--human` — первой строкой.
- Панель: та же строка; вопрос владельцу в источнике задач
  (`sourceQuestions[].tasks`) при готовых работах тоже называет запуск ходом
  ведущего.
- Skill `harness`: ведущий запускает `run` для готовых работ, прежде чем
  закончить сессию в ожидании ответа владельца.

## Совместимость

- Новое событие `environment.reconciled`: alpha.66 читает его как `unknown`.
- Хост с собственным draft (`planDraft(..., {keyOrder})`): общая форма задачи
  draft не менялась; `kind`/`gateChanges` — только в draft самостоятельного
  проекта.
- Хост, отображающий виды транзакций: новый вид `environment.reconciled`.
