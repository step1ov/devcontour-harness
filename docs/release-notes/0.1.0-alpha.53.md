# devcontour-harness 0.1.0-alpha.53

Выпуск снижает цену выдачи (`claim`) на доске с длинной историей попыток:
учёт бюджетов при выдаче больше не перечитывает всю историю на каждом
вызове. Для авторов хранилищ хоста добавлен необязательный метод
`ExecutionView.pristine()`. `stateVersion`, `policyVersion`,
`handoffVersion` и `reportVersion` прежние; записи хранилища и ответы
команд не меняются.

## Изменения

- **Цена выдачи пропорциональна живой работе, а не истории.** Прежде каждый
  `claim` пересчитывал удержания бюджетов для каждого готового поручения
  отдельно: области поручения, группы и общего бюджета заново читали все
  попытки, а записи вызовов без поручения искали свою попытку в каждой
  области. Один холостой `claim` читал порядка `(1 + 3 × готовых) × попыток
истории` записей плюс все записи вызовов. Теперь:
  - без готовых поручений учёт бюджетов не выполняется;
  - общий бюджет, бюджеты групп и попытки без записей вызовов считаются один
    раз на выдачу (`workBudgetsOf`) с теми же ответами, что у
    `workBudgets`; каждое готовое поручение по-прежнему оценивается в свой
    момент `Date.now()`, поэтому причины и события `budget.blocked` прежние;
  - записи вызовов, попытки без записей и связь записи с поручением
    запоминаются по хранилищу (`host.store`) и `dataVersion`, прочитанной в
    начале выдачи до записей транзакции; пока данные не менялись, повторный
    `claim` не читает историю вовсе;
  - память используется и пополняется только в «чистой» транзакции
    (`pristine()`, ниже) и только когда нет активных записей вызовов: их
    длительность зависит от монотонных часов и живости владельца, поэтому
    она считается заново;
  - число активных попыток берётся быстрым путём `activeAttempts`, без
    проекции всей истории.
- **Замер.** Микрозамер `scripts/bench-claim.ts` (холостой `claim` на доске,
  где выдавать нечего, история с записями вызовов, SQLite):

  | Попыток в истории           | Прочитано попыток за `claim`, было → стало | Надбавка бюджетов, было → стало |
  | --------------------------- | ------------------------------------------ | ------------------------------- |
  | 250                         | 6 275 → 0                                  | ≈6 мс → ≈1 мс                   |
  | 1 000                       | 25 025 → 0                                 | ≈21 мс → ≈11 мс                 |
  | 4 000                       | 100 025 → 0                                | ≈107 мс → ≈50 мс                |
  | 4 000, записи без поручения | 164 025 → 0                                | ≈628 мс → ≈57 мс                |

  Надбавка — разница между `claim` с бюджетами и без них на той же доске;
  абсолютные числа зависят от машины. Записей вызовов за `claim` прочитано
  0 вместо числа попыток истории. Первый `claim` после изменения данных
  читает историю один раз.

- **`ExecutionView.pristine()` для авторов хранилищ.** Новый необязательный
  метод: `true` значит, что транзакция внешняя (не вложенная) и ещё ничего
  не записала — ни записей модели, ни локальных записей, ни событий; тогда
  видимые данные ровно те, что зафиксированы при текущей `dataVersion`.
  Вид чтения и вложенная транзакция возвращают `false`. Хранилище вправе
  вернуть `true`, только если:
  - `dataVersion` меняет каждая фиксация любого писателя (другого процесса,
    другой версии пакета), изменившая записи модели или локальные записи;
  - прежнее значение `dataVersion` не повторяется для других данных;
  - объекты, прочитанные в транзакции, не меняются после её закрытия.

  Иначе метод возвращает `false` или отсутствует — тогда движок
  пересчитывает учёт при каждой выдаче, как прежде; ответы одинаковы в
  обоих случаях. Встроенное хранилище SQLite реализует метод и требует
  метку `leaseRows` в базе: без неё в ту же базу может писать прежняя
  версия, которая `dataVersion` не меняет. Память движка не переносится
  между разными хранилищами с равной версией.

## Совместимость

- Ответы `claim`, удержания бюджетов, причины и события прежние; тесты
  сверяют записанные удержания с замороженным эталоном при новых записях
  вызовов и попытках без записей между выдачами, при вложенной транзакции с
  незафиксированной тратой, откате транзакции, записи из другого соединения
  и смене хранилища.
- Хранилище хоста без `pristine()` работает как прежде, без экономии.
  Хранилище, которое добавляет метод, должно выполнять гарантии выше:
  неверное `true` даёт устаревший учёт бюджетов при выдаче.
- Откат на 0.1.0-alpha.52 не требует действий с данными.
- Подробности — [upgrade](../upgrade.md).
