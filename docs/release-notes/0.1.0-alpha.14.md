# devcontour-harness 0.1.0-alpha.14

Проверка по закреплённым эталонным наборам в договоре проверки и несколько
gates у одного обязательства. Gates, `maxAttempts`, бюджеты попыток и
повторов, правила находок, изоляция, принятие target ref и генеративная
проверка (`property`) не менялись.

## Что нового

- **`verification: "reference"`.** Вычислительное обещание (оптимальность,
  полнота, точность, производительность) можно проверить не генератором, а
  наборами ответов независимого эталона, посчитанными заранее и закреплёнными
  артефактами контракта. Обязательство описывает эталон и его пределы
  (`oracle`), сверку эталона с другим способом (`crossChecks`: семейство,
  способ, совпало из всего), наборы (`sets`: gate, файлы, доля входов и
  семейств) и то, чего наборы не доказывают (`gaps`). Gate такого
  обязательства — обычный test-gate без `property`
  ([договор](../contracts.md#способы-исполнения-обязательства-property-и-reference)).
- **`obligations[].gates`.** Обязательство называет свои gates (1–10); без
  поля его исполняет `checks.gate`, как раньше. Генеративное обязательство
  проверяет полное покрытие на каждом своём gate; эталонное — долю наборов
  каждого gate.
- **Доказательство доли.** Gate, которому манифест поручения назначает
  эталонное свойство, получает путь отчёта свойств и селектор и без
  `gate.property`. Отчёт обязан назвать свойство со статусом `passed` и
  числом проверенных входов и семейств не меньше доли этого gate, JUnit —
  testcase с тем же ID; зелёный JUnit и код 0 без отчёта — отказ gate.
  Приёмка требует запись с манифестом от каждого gate обязательства.
- **Структурные отказы до вызова модели:** gate обязательства без набора,
  набор чужого gate, файл набора не среди артефактов контракта, доли наборов
  меньше общего минимума или минимума семейства, семейство набора не из
  покрытия, сверка эталона с расхождениями, корпус у эталонного
  обязательства, корпус генеративного обязательства не на gate договора.
- **Reviewer контракта** получает эталонные обязательства отдельно: эталон,
  сверку, наборы и `gaps` (`referenceNote`). Обещание, которое опирается
  только на `gaps`, — блокирующая находка.
- Самопроверка исполнителя запускает и gates эталонных наборов.

## Изменения договора

Добавления в `checkDeclarationSchema`: `obligations[].gates`,
`obligations[].verification` (`property` | `reference`) и
`obligations[].reference`; в `CheckManifest.properties[]` — `reference`
(только у эталонных свойств). Новые экспорты: `obligationGates`,
`isReference`, `referenceNote`, `expectsReference`, `referenceSchema`. Без
новых полей разбор, отказы, манифест, его digest и основание корпуса
(`suiteBasis`) те же, что в alpha.13. Сообщение «… не генеративный (нет
property)» теперь называется для каждого gate генеративного обязательства.

## Совместимость

Формат состояния тот же. Договор с новыми полями alpha.13 и раньше не
принимают (строгая схема): состояние с таким контрактом откатывается только
через копию. Обновление и откат — по [upgrade](../upgrade.md).

## Проверка выпуска

`npm run check` (lint, typecheck, schemas, build, весь набор тестов, package
smoke из установленного архива) на macOS arm64, Node.js 24.3.
`tests/reference.test.ts`: структурные отказы и принятый договор на gates без
генератора, манифест доли gate, прежние манифест и основание корпуса
договора без новых полей, согласование поручения, подсказка reviewer,
самопроверка; на fixture runtime — два gate эталонных наборов доводят
поручение до приёмки, недобор входов при зелёном JUnit и коде 0, отсутствие
отчёта и расхождение с эталоном — отказ gate. Каждая новая проверка падает на
своём мутанте реализации. Живые модели не вызывались.
