# devcontour-harness 0.1.0-alpha.7

Исправление учёта фактически выполненных команд reviewer в `inspection` ревью
кода. Gates, `maxAttempts`, бюджеты попыток и повторов, правила находок, защиты
worktree и принятие target ref не менялись: `inspection` по-прежнему описывает
evidence и не влияет на решение.

## Что исправлено

- **Проверки reviewer не учитывались.** На пилоте alpha.6 reviewer запускал
  проверки через `run_check` (в том числе объявленные gates), а `inspection`
  оставался `diff-only` с пустым списком команд: учитывались только shell-события
  Codex. Теперь итог собирает controller из событий runtime и журнала
  `probes.jsonl` одного вызова reviewer; самоотчёт модели по-прежнему ничего не
  подтверждает.
- **Ненулевой код выхода превращал выполнение в `diff-only`.** Режим зависел от
  наличия команды с кодом 0. Теперь `mode: commands` — любая подтверждённая
  выполненная команда; провал теста — исход, а не отсутствие выполнения.
- **Уже отменённый вызов проверки запускал команду.** Слушатель отмены на уже
  отменённом сигнале не срабатывал, и команда шла до таймаута. Теперь такой
  вызов — `cancelled` без запуска.
- **Код и вывод терялись при сбое после исхода** (уборка временных каталогов,
  сохранение evidence gate): исход сохраняется как `error`/`environment` с
  кодом и выводом.
- **Короткий секрет портил разбор событий Codex** и служебные значения
  записи: события разбираются из немаскированного потока только в памяти,
  маскируются поля текста до обрезки; сохраняемые журналы маскированы, как и
  раньше.

## Граница старта

Запуск probe засчитывается по признаку `started`, полученному на границе
исполнения `runCheck`: без песочницы — порождение процесса, в песочнице — метка,
которую обёртка создаёт перед `exec`. Отказ до старта, исчерпанный бюджет,
неизвестный gate, отменённый до запуска вызов, резерв `start` и `abandoned`
выполнением не считаются; они перечислены в `inspection.excluded`.

## Изменения договора

Только добавления и nullable — подробно в
[review-probes](../review-probes.md#итог-inspection-что-reviewer-действительно-выполнил):

- `inspection.source`: новые значения `controller-probes`,
  `runtime-and-controller`;
- `inspection.commands[].exitCode` может быть `null`; новые необязательные
  `origins`, `status`, `failure`, `gate`, `note`;
- новые необязательные `inspection.context`, `total`, `excluded`,
  `excludedTotal`, `invalid`;
- строки исхода `probes.jsonl` и `review.json.probes`: `started`, `scope`,
  `exitCode`, `note`;
- `runCheck` возвращает `started` и принимает `onStart`; `command()` —
  `onSpawn`, `onRawStdout`.

Полный `inspection` в `run-result` не добавлен; публичные схемы, кроме
`execution-document`, не менялись.

## Совместимость

alpha.7 читает состояние alpha.6 без преобразования и без пересчёта прежних
`inspection`, digest и решений. Направление одностороннее: строгая схема alpha.6
не принимает новые значения `source`, `exitCode: null` и новые поля, поэтому
откат с alpha.7 — только восстановлением копии состояния, сделанной до
обновления ([upgrade](../upgrade.md)). Потребителю, разбирающему `inspection`,
нужно принять новые значения enum и nullable `exitCode`; признак выполнения —
`mode`.

## Проверка выпуска

`npm run check` (lint, typecheck, schemas, build, весь набор тестов, package
smoke) на macOS arm64, Node.js 24.3.0. Матрица приёмки IN01–IN20; независимая
приёмка другой моделью воспроизвела IN01–IN19 собственными прогонами.
