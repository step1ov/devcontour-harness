# Один вендор

Writer и reviewer — claude. Это разрешено только потому, что каждое правило
ревью явно говорит `"vendor": "same-vendor-allowed"`. Без этой строки
`harness validate` отклоняет политику (`REVIEWER_SAME_VENDOR`).

Что сохраняется и при одном вендоре:

- reviewer — отдельная роль и отдельный вызов со свежей сессией: в его запросе
  нет разговора, отчёта и идентификатора сессии writer;
- reviewer получает исходные критерии приёмки, закреплённый контекст, diff,
  evidence проверенного SHA и прежние находки;
- reviewer работает только на чтение: правка дерева или HEAD делает его
  ответ недействительным;
- приёмка требует тех же gates и ревью обеих фаз; разные модели не нужны.

Тот же эффект для одного runtime без смены вендора по умолчанию даёт
`alternates`: reviewer `codex`, запасной `claude` — для автора codex будет
выбран claude только при `same-vendor-allowed`.
